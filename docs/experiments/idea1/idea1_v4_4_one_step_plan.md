# v4.4：Kalman起点能否支持纯一步AE闭环

用户授权对照：Full只刷新残差，全部实际动作由一步AE生成，关闭验证与回退。新跑两条件各40条探索闭环，LIBERO四套件task0–9、官方init19，共80条；不重新调参。

沿用v4.2已经提取的固定V12子路径，跳层[2,3,5,14,16,17]。它是已有固定mask，不是v4.3动态非相邻选层策略；本轮不反传、不选层，避免Full-D10选择器计算混入“仅一步AE”。两组同模型、mask和残差历史规则，只改变AE起点和对应积分区间。每次重规划AE均为NFE1，包括首轮和残差刷新轮。完整18层AE不跳层，encoder和AE均不上CUDA Graph。

- `v12_d1_gaussian_refresh`：高斯噪声起点，t=1→0，一步Euler。
- `v12_d1_kf6_refresh`：六维命令Kalman，固定v4.3冠军tau=.75、rho=1；x_tau=.25*KF_raw+.75*epsilon，从.75→0一步Euler。只预测位移及旋转增量，夹爪保持最后执行值；原滤波参数和旋转单位协方差形状不变。首轮没有已执行动作历史，与高斯组完全相同地使用t=1的一步AE；之后仅ack真实已执行命令（前六维按控制器clip）进入滤波，未执行的H50尾部不得进入。

两组均每三轮（replan0/3/6…）用当前观测完整VLM提取跳层FP32真残差，不调用Full AE、不执行Full动作。随后重新运行V12并加入自身最近两份残差的线性外推；刷新轮ratio0，第一周期hold，其他轮按实际age/gap外推。无验证器、无夹爪保护、无Full回退。沿用π0 BF16 checkpoint、修正OpenPI linspace时间嵌入、H50/R5、20Hz仿真控制频率、seed7、10步settling、原prompt/上限和case/replan噪声。与v4.2一样快速仿真，不人为sleep墙钟20Hz；本轮重点是动作质量，不把CPU串行实现的开销当成算法下限。

同case两条件同服务/同GPU、次序轮换，每条件新建同seed环境，核对首观测、初始化和首轮原始动作在atol=rtol=1e-5内一致。只记录必要动作/EEF/原始H50/路由与计时，无视频。针对性CPU核验只有一步、残差日程、首次高斯、只吸收ack、reset隔离；四套件真实输入GPU检查残差Triton加法与PyTorch参考、Kalman坐标编解码及重复调用一致，禁止Full/legacy AE与验证入口。失败不改容差。

主要终点为闭环成功数、配对恢复/新增失败、执行步数；一步AE是否足够以没有Full接管的实际结果判断。另报AE与实际策略热态ms/动作、准备成本、墙钟和吞吐。已完成v4.2同协议高斯D2残差刷新32/40作为历史质量参照，固定其结果哈希，不冒充同轮计时。40例是探索评测，tau参数曾在相关40例上选择，本轮不是未见任务的独立统计确认。

仅使用自然释放、无计算进程且显存≤1500MiB的卡；单调度者每30秒检查，连续空闲60秒后按UUID共享锁领取，最多4卡。每卡一个持续B1服务；有界技术重试一次，资源冲突只退出自有进程，不干预他人。全部结束释放服务和租约，结果保存results/idea1_v4_4_one_step，不修改旧策略和历史结果。
