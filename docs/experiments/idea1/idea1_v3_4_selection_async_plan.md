已完成前一轮：`results/idea1_v3_4_selection_cost`。无图串行/2+2/四方向为2019.50/1355.44/909.80ms；图四方向371.90ms，P95 380.78ms。图保持无图批量的结果，但批量相对串行梯度未过既定容差，16次V12/V14选层有1次不同。组合评分64例已审计：V12/P3 8→7，V12/P5 7→7，V14/P3 7→8，V14/P5 8→8，每项n8，首前缀异常0。第二项曾按用户要求暂停；新目标仅在证明重叠后恢复其2/3实际Full间隔候选。

## 执行顺序

1. 固定8真实输入小探测。按算子profile四方向图路径；尝试保持注意力掩码数学语义的实现和有界编译，不改Full-D10/权重/方向。每候选保存速度、准备、显存、raw、四方向梯度、层分数、合法选层。编译单候选最多5分钟，整段约10–20分钟，不无限优化。
2. 对同输入测串行、shadow图与原生AE双stream（默认/推理高优先级），并测0/100/250/500ms执行窗口。记录当前动作就绪、梯度就绪、下次Fast等候、总GPU工作；用CUDA事件和少量trace验证真实kernel重叠。当前梯度依赖可微AE输出，原生Triton没有可直接复用的反向激活，不能宣称VLM完毕便已能得到完整VJP。
3. 重叠首先严格等待本次Full选层完成后再运行其后Fast，保持选层时效；每个实际Full独立刷新外推历史。pending任务绑定episode和Full步，不能跨场串缓存或覆盖未完成输入。若改为旧mask放行，必须另列科学变体。
4. 固定40case（4 suites×task0..9×init19）探索闭环，优先V12、周期3/5；同步/异步按同case配对。已完成的8例能证明协议及共同前缀兼容才复用；无重复有效失败。根据算子/重叠结果选择有限候选，测试q1/q2及两种评分；条件间共享确定性预热/有界图缓存，不共享可变episode状态。
5. 重叠成立后单独测试每2/3次实际Full选层。最终对Full-D10报告成功数/配对变化、策略临界路径ms/实际动作、实际闭环wall、episode/小时、动作就绪及残余等待。模拟执行真实wall和统一20Hz的部署窗口分开报告；不得只给候选加sleep后声称提速，或把GPU总工作忽略。1.5倍未达到则按Full比例、验证、拒绝接管、剩余梯度等待和执行长度分解。质量下降则用少量保存请求做当前Full-D10离线shadow、验证假接受/外推/选层诊断，不泄漏到正式候选。

资源：启动时GPU1/3空闲；GPU0已有其他模型，GPU2原有任务继续占用，不抢占。只领取无compute进程且<=1500MiB的卡，持共享UUID锁；一个调度者发现空闲卡，已有足够资源不重复全卡扫描。CPU/B1服务持久化，每case条件保持同卡。所有执行revision和调整记录到独立新目录。
