# idea1 v3.4 实验方案

2026-10-28。依据当前 idea1.md 的 v3.4 E1 与 E3；E2 内容为空，不编造实验。原始 idea1.md 不改写。临时 kv_reuse_probe 仅作历史参照，不计入新闭环分母。

## E1：旧 Full KV、真实计算截断与 Spatial

固定 π0 原 checkpoint、BF16 原生 Triton、原始 1-based V14 mask [3,4,9,11]、H50/R5、D2 原生均匀 Euler。Full 刷新 D10。四套件各 10 task，init14 初筛 40 条/条件；主条件 Full-D10、纯 V14-D2、周期 V14-D2、周期 hybrid-L16 各固定补至 init14–18，共200条/条件。不按初筛成绩挑选主条件。诊断条件 Full-D2、周期 hybrid-L13、周期 hybrid-L12 各40条。总 E1 920条。Spatial 单列50条/主条件；四套件等权，配对 case 比较，按 suite 分层 task 聚类 bootstrap 95%区间。探索规模，非官方50 init全量评测。

周期路径：每个 episode 首次 Full-D10，此后两次 draft-D2，再 Full-D10；无 verifier 或夹爪保护。周期 V14 与 hybrid 只差 KV 替换与对应计算截断。hybrid 的早层用当前观测 V14、从 cutoff 层起用最近一次 Full 快照；旧 Full 严格只由本路径自身已执行历史生成，draft 不覆盖 Full。缓存 age 为5/10个实际控制步（终止不足5步另记），不是每帧免费获得 Full。当前 state、当前噪声始终新鲜。统计中计入所有刷新成本。

实现实际停止从 cutoff 开始的 VLM 投影及隐藏更新，并跳过最后一层当前 KV 生成后的无用 hidden 更新；vision 仍完整。GPU 对照须证明与“完整计算当前 V14 再换尾部 KV”原始/decoded 动作在 atol=rtol=1e-5 内一致；另报实际最大差，不事后放宽。保留独立 Full KV，检查 reset、ack、不跨episode缓存。

机制重放使用新的 Full-D10 真实轨迹，每条轨迹按请求索引均匀选4点、严格上一请求/5动作来源，最多800对；初筛阶段先40轨迹160对，主分析固定这160对避免边做边扩。D2与D10在同一组样本比较。逐层单层替换 L1–18、后缀 L12/L13/L14/L15/L16/L17/L18、全旧，以及相同替换位置的当前 Full oracle。后者只能作机制对照，不作可部署加速结果。K/V相对L2、余弦、范数，prefix平移/旋转/夹爪误差，分suite、观测变化量与age。用单层、整段、oracle对照区分旧观测误差、跳层误差和跨层组合非线性；不能凭相关性断言唯一机制。只在需要的160对上保存必要动作/指标，不保存全量激活。

同卡固定输入在各shape/路径预热后交替AB/BA，测完整请求 wall、vision/VLM/AE及截断前后；同时报闭环 policy累计wall/实际动作、每请求和episode/小时、加载/编译成本。自由闭环episode长短与同输入推理加速分开。

## E3：被拒 draft 的相关性、修复与剩余动作初始化

另运行40条独立 strict D2父系统闭环（同init14）：V14-D2，tau0.10、原双时刻0.10/0.05验证、P2、strict夹爪、Full-D10。保留所有路由统计。预先取每episode最早4个零接受请求及最早2个非零接受请求，记录全分母与未抽中计数；不因动作误差挑样。部分接受与零接受、空间/夹爪因素分别报告。

在这些实际父系统状态上只做shadow，不执行修复动作：同输入同噪声当前 Full-D10 参考、当前 V14-D2/D10（隔离步数和特征）、被拒draft在当前 Full KV下重加噪 q=0.1/0.3 后2步 Euler修复、同 q=0.3在原 V14 KV下2步修复（条件消融）。初始化 z=(1-q)*draft+q*显式新噪声，时间从q积分到0；新增AE成本与已付draft/verify成本分别保留，并与fresh Full整体请求成本比较。修复不能免费获得当前Full KV，部署成本须计入其构建。

上一轮剩余动作：只用本路径上一轮真实提出并实际执行前缀对应的剩余normalized动作，前移真实执行长度，尾部保持末动作；在q=0.3重加噪后2步，分别用当前Full/V14条件。缺历史时标记不可用。对比当前 Full-D10 的raw/decoded前5/全50平移旋转夹爪误差、逐请求余弦与跨样本相关性、改进比例、原验证器重新接受率。相关性、离线误差与验证接受率均不能解释成修复策略闭环成功率；本轮E3是按文档提出的问题做机制验证，若值得闭环必须另命名/冻结实验，不能拼接成功率。

## 协议、执行和交付

20Hz、官方初态、原prompt、10步开夹爪settling、环境seed7，步数上限Spatial220/Object280/Goal300/Long520；噪声沿用idea1-v22固定suite/task/init/request哈希，完成顺序不影响。每条件逐case保存官方初态/bddl/checkpoint/源码/manifest身份、原始/decoded动作、真实EEF XYZ/quaternion、执行长度、success oracle、缓存age、模块与RPC时间。Full-D10轨迹保存模型观测供E1机制；E3抽样保存实际观测/噪声身份及所有候选动作。无视频，B1持续服务、单环境worker/卡，按case分片；不为吞吐引入神经网络batch。GPU1本轮排除，启动检查0/2/3实时归属，不停止其他任务。
