# idea1 v3.3 实验设计与执行方案

日期：2026-10-24。本文冻结 v3.3 的科学问题、样本与决策规则；E2 的姿态变化阈值数值须在首条 E2 正式案例前完成预先规定的校准并冻结。四个实验独立改变父系统；未经单独命名和评测，不组合 D1、Kalman 与软验收。使用普通 LIBERO 四套件，不把 Plus 或跨环境成绩混入本轮分母。

## 1. 事实依据与共同协议

1. π0 的原有验证时间点是 `t=(0.10,0.05)`；`tau` 是空间接受半径，不是加噪时间点。原空间规则对未来最多 5 个动作的前六维计算两分支重建误差，允许连续前缀的部分接受。零接受与夹爪事件分别处理。实现入口：`preparations/idea1_v3/policy.py`。
2. D1 比 D2 更不稳定尚属假设，须保留同阈值对照；不能先放宽阈值再把成功率变化归因于 D。
3. 冻结 v2.1 Kalman 的状态是三维平移控制命令及其变化趋势，并不生成旋转或夹爪；此前数值是与 Full 命令的离线差，未验证此路由的独立闭环成功率。证据：`docs/experiments/idea1/idea1_v3_2_report.md` 第 3 节。
4. Xiaomi 新 `skip12 short-runs` mask 为 `[4,5,6,13,14,15,22,23,24,31,32,33]`，历史 Full-D2 为 195/200、skip12-D2 为 185/200；这些成绩只属于对应旧 200 案例。证据：`docs/experiments/idea1/idea1_v3_1_final_report.md` 第 4 节。
5. v3.2 的 B4 固定输入 bank 1.51× 是 bank 吞吐，不是闭环评测加速；Plus 数据也未识别纯 draft 退化的容量因果或扰动类型贡献率，不据此选本轮样本。

共同任务为 Spatial/Object/Goal/Long 各 10 个官方 task，20 Hz、原指令、原 checkpoint、10 步开夹爪 settling，步数上限分别 220/280/300/520；沿用各原路径官方初态和确定性请求 seed。每条件先跑 80 条：π0 每 task 用 init6、7，Xiaomi 用 init0、1。入选后补 220 条：π0 加 init8–12 和每 suite 偶数 task 的 init13；Xiaomi 加 init2–6 和每 suite 偶数 task 的 init7。最终每套件 75 条、共 300 条。首批 80 计入 300；保留 `first80/new220/all300` 三种口径。300 不被 40 整除，额外 init 的 task 集合预先固定。历史案例只有在 checkpoint、obs/prompt、seed/noise、init/settling、H/R/D、mask、终止规则和执行 revision 可比时才能逐键复用。技术 invalid 与科学失败分开。

π0 父系统固定为 V14 skip `[3,4,9,11]`、draft D2、H50/Rmax5、`tau=0.10`、`P=2`、原 strict 夹爪规则，startup/periodic/reject 等 Full 均 D10。Full KV 独立保存，draft 不能覆盖；P 以 draft 轮计数。每轮只执行被允许的预测前缀并按实际执行数 acknowledge。π0 的共同基线为 Full-D10、Full-D2、纯 V14-D2、严格 D2 父系统。Xiaomi 共同基线为 Full-D2、纯新 skip12-D2；本轮 Xiaomi draft 和 Full 均 D2/H10/Rmax10，P=2。

主成本口径为 **完整策略推理累计 wall / 实际执行动作数**，计入被拒 draft、verify、Full 接管、输入输出变换；另列每请求成本、模型模块时间、闭环 episode/小时、准备/编译时间。速度比仅在同 GPU、同后端、同输入和相同计时边界下给出；Full-D10 与 Full-D2 分别列示。质量主指标为有效 episode 成功数，逐 suite、逐 task、实际步数及失败上限分布同时报告。配置、源码/checkpoint/manifest hash、case key、seed/noise、路由、接受长度、实际动作与真实 EEF XYZ/姿态、时延和成功 oracle 必须保存。默认不录视频。

## 2. E1：π0 V14-D1

五个初筛条件，每项 80 条：纯 V14-D1（无 verify/Full）以及 V14-D1+strict verify 的 `tau∈{0.10,0.15,0.25,0.40}`。D1 为一次原生 Euler 更新 `1→0`；除 D 和 tau 外，P、gripper、Full-D10 和两个 verify 时间点均与父系统相同。纯 D1 作为诊断，不能与带 Full 的成功率直接解释为验证器收益。

同 `tau=0.10` 的 D1/D2 是单因素对照。报告成功、执行前缀长度、每动作成本、Full 调用与原因。保存两个重建分支的逐动作空间误差、首次超限位置、超限动作数、最长连续超限段；将空间零接受、空间部分接受、重建夹爪切换、draft 夹爪截断及 pending Full 分开计数。这些是路由触发因素，不直接标成最终任务失败原因。

## 3. E2：姿态感知的 Kalman/V14 路由

沿用冻结 v2.1 Kalman 参数、协方差和只吸收已执行动作的更新规则。其 H50 XYZ 预测经原命令裁剪；旋转及夹爪命令保持最后实际执行值。用当前状态的原生动作 decoder 的逆变换把七维命令映射到 π0 normalized action 空间，padded 维置零，并对真实样本核对命令→normalized→decoded 往返。不得将七维命令直接作为 normalized 原始张量。Kalman 分支仅准备当前 state/必要元数据，不执行当前 vision/VLM 或 learned draft head。Kalman/V14 均走父系统相同 verify 和 Full-D10 接管。

路由优先级：startup、pending gripper、periodic Full 优先；上一轮**实际执行过** Kalman 动作，本轮非 Full 分支强制 V14；其余轮须同时通过 a/b/c 与共同约束才走 Kalman，否则 V14-D2。两种 draft 都计入 P=2。零接受先付 draft+verify 成本再 Full；只将最终实际执行动作反馈 Kalman。 episode reset 清全部历史、Full KV 和路由状态。

a 为最近五条实际执行的三维平移命令的最大相邻方向转角；b 为最大相邻平移命令 L2 变化。三个档位为 `(10°,0.02)`、`(20°,0.05)`、`(30°,0.10)`；b 在解码后、实际送入仿真环境的控制命令坐标中计算，是命令变化代理，不是 EEF 世界坐标位移，也不是 π0 模型的 normalized action。两向量均近零（范数 `<1e-4`）时转角 0，仅一向量近零则不通过。

c 为**末端世界坐标姿态变化门控**。俯仰角、偏航角、翻滚角描述该姿态，但门控用四元数避免欧拉角的角度回绕：从最近五个连续**实际完成控制步**的 EEF 世界坐标四元数计算窗口内最大两两相对旋转角 `Δθ_c=max_{i<j} 2 arccos(clip(abs(dot(normalize(q_i),normalize(q_j))),0,1))`。仅当 `Δθ_c < θ_c` 才允许 Kalman；`Δθ_c ≥ θ_c` 时走 V14-D2。四元数 `q` 和 `-q` 表示同一姿态。历史不足五步、姿态缺失/非有限/范数接近零时选择 V14。共同约束：最近五条夹爪命令无符号切换，旋转命令最大相邻 L2 变化≤0.05。c 使用真实观测，不使用未来预测姿态。

`θ_c` 的具体数值**待确定**。先用 π0 父系统首 80 条已执行控制步的姿态变化分布校准三个探索档位，只看姿态数据，不用成功标签或 E2 结果挑阈值；保存分布、档位选取规则、三个数值、案例清单与源码/manifest hash 的校准收据，并在首条 E2 正式案例前冻结。草案中的 `2°/5°/10°` 仅是待核对的候选值，不视为已校准阈值，也不因 E2 成败回调。三个冻结档位与 a/b 三档交叉，最多九个门控条件；若姿态数据不足以合理区分三个档位，先记明原因并修订条件清单，不把未定阈值作为正式结果。

另设一个不检查平稳性但仍禁止连续 Kalman、保留 verify/Full 的交替对照。最多九个门控与交替对照各 80 条；门控候选选出后再做一个**仅移除 c** 的同案例消融，最多 11×80=880 条。若九条件均不达扩样门槛，也按最高成功数、最低成本选择一项做移除 c 的诊断，但不扩样。报告各约束单独与联合阻止的请求数、Kalman 实际执行率、Full 接管率、替代的 V14 次数及完整成本；姿态变化小只代表允许尝试 Kalman，不等于已证明无需视觉观察。

## 4. E3：软空间验收

固定父系统的 V14-D2、tau=0.10、P=2 与 strict 夹爪规则。对动作 `j` 定义 `e_j=max_k RMS_6(hat[k,j]-draft[j])`。候选连续前缀长度 `L=1..5` 合格当且仅当：每步 `e_j≤ατ`；`e_j>τ` 的动作最多一个；`sum_{j≤L} e_j²≤Lτ²`。取最长合格连续前缀，仍按原顺序执行，再应用原夹爪检查；绝不跳过中间动作。

初筛四条件各 80 条：软规则 `α=1.25、1.50`；标准硬规则 `τ=0.125、0.15` 作为相应“只放宽半径”消融。报告成功、空间零接受、实际执行长度、verify/Full 次数和每动作成本。增加接受率本身不作为成功判据。

## 5. E4：Xiaomi skip12-D2＋verify

**不设任何夹爪保护：**验证器仅检查前六维空间误差；重建或 draft 的夹爪符号变化均不拒绝、不截断、不产生 pending Full。实际夹爪仍按原模型 decoded 输出执行；切换事件仅作诊断。P 始终为 2，Full 原因为 startup/periodic/空间零接受。部分空间接受执行允许的连续前缀，随后真实重规划。

Xiaomi flow 的时间方向为噪声 `t=0`→动作 `t=1`，因此必须实现自身的单步重建。对 `q∈{0.10,0.05}`：`z=(1-q)·draft+q·noise`，在 `t=1-q` 预测速度，`hat=z+q·v(z,1-q)`。复用最近 Full 的独立 KV 快照，使用当前 state、原生 action mask/位置编码，两个验证时间点先分别执行 AE。空间误差在 Xiaomi 自身 normalized 六维空间计算，**不直接沿用 π0 的 tau 数值**。首批核对 Full 与 skip12 的原生 D2 等价性及相同输入/噪声重复性。

独立搜索 `tau={0.025,0.05,0.10,0.20,0.40,0.80}`，每项 80 条；另跑同 P=2、无 verify、也无夹爪保护的周期 Full 对照 80 条。若 80 条的质量—成本 Pareto 前沿包含搜索最低或最高边界，各追加一次 `tau=0.0125` 或 `1.60` 的 80 条边界探针；不得继续无界扩网格。至多九条件、720 条。阈值在扩样前冻结，新增 220 条不再调参。与纯 skip12、Full-D2 和无 verify 周期 Full 逐例比较，分别检验混合策略收益及 verifier 的增量价值。

## 6. 筛选、预算与统计

E1–E3：首 80 条相对严格 D2 父系统最多净少成功 2 条，完整每动作成本至少下降 10%，方可扩样。E1 至多两个不同候选（成本最低者、成功数最高者）；E2/E3 各一个（成本最低→成功数最高→较保守参数）。无合格者停止该分支扩样。E4 至多一个质量候选（较纯 skip12 增加成功数）和一个成本候选（较纯 skip12 净少成功≤2/80且成本下降≥10%）；重合则只扩一个。无 verify 周期对照随 E4 入选项补齐相同案例。E1纯D1、E2交替/移除c、E3对应硬半径消融按入选项必要案例补齐。

全部初筛与有界补点最多 2320 条，最多六主候选的增量为 1320 条，五项必要消融增量最多 1100 条，六共同基线在完全无法复用时最多 1800 条；总科学闭环硬上限 **6540 条**。实际任务量按有效兼容复用、未触发边界/扩样分支扣减，不为用满上限补跑。结果在 300 条上下降≤2.5个百分点对应最多净少成功 7 条。报告配对恢复/新增失败、逐 suite 和 task 等权成绩、按 suite 分层的 task 聚类 bootstrap 95%区间。初筛选型门槛不是总体成功率非劣的统计证明。

## 7. 工程执行、验收与交付

实验执行优先 E2/E4，其次 E1/E3。四张 GPU 均获授权，但每次派发前检查实际占用、UUID与其他进程；同卡持续模型服务、B1 请求。先用约 10–20 分钟真实案例 profiling 测完整 episode/小时、动作/秒、请求/秒及服务加载、仿真/reset、渲染、RPC、推理、I/O，至少覆盖四套件各两个固定案例。双环境 worker 需在相同工作负载上通过状态隔离和闭环吞吐对照才采用；无需神经网络 batch。多卡按唯一任务键分片，固定 seed 与完成顺序无关；已有效失败也是完成，不重试到成功。缩减非必要 I/O，保留策略相机及研究所需遥测，不录全量视频。首次编译/加载单列；固定输入请求测速不可当作正式闭环速度。

验证覆盖：D1 一次 AE、旧严格 D2 路由不变；Kalman 无未来信息、七维动作往返、Kalman 分支 vision/VLM 调用为零；四元数 `q/-q` 等价、±180°附近连续、累计转动、异常/缺失姿态、执行步对齐；软规则孤立/连续/首步/严重超限；Xiaomi 重建时间方向、原生 mask/KV、P=2 与完全取消夹爪保护；零接受与部分接受的实际动作、episode 间历史/KV/随机流隔离。服务重启与跨 GPU 的数值要求沿用当前项目既定门禁，不为放行调大容差。采用同输入真实动作核验，首个正式案例计入清单，不叠加大规模验收试跑。

交付：本方案、冻结 manifest、执行状态、四项实验中文报告、逐案例与逐请求机器可读数据。报告必须区分模块加速、固定请求加速、闭环每动作成本和完整评测吞吐；记录未启动、技术中断、有效失败及统计边界，不以推断替代测量。
