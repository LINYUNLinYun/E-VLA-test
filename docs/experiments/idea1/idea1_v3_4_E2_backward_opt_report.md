# E2 单次反传加速实测

2026-10-30。结论：159ms 不是当前 Jacobian 方法的计算下限。保持单动作、同一随机投影与门控定义，CUDA Graph 已将前向+一次 VJP+CPU 选层做到平均 64.01ms、P95 64.65ms。确定性普通 PyTorch 同轮 205.37ms，约 3.21×。四次投影完整耗时 185.67ms、P95 187.74ms。先前 158.6ms 是历史普通 BF16 测量，不能用跨轮数据代替本轮配对。

## 条件与口径

一张独占 RTX4090，PyTorch 2.7.1+cu126，冻结原导出模型，BF16 权重/激活、FP32 RMS，D2/H50/R5。第一步动作七维，17 个 VLM 门控，seed340710 的原一/四组 ±1 权重；skip4、最长连续两层。4 套件各 task0/2 的八个真实请求，每方法每请求十次热测。原模型及历史实验未修改。输入、state、prompt、噪声身份见 manifest。

总时间包含 VLM+完整两轮 AE/FM、VJP、梯度送 CPU、约束选层和动作输出，边界同步；Graph 输入缓冲更新也计时。固定视觉嵌入已就绪，不含视觉编码、RPC、加载或捕获。故这些数字不能直接当作机器人完整服务时延，也不能直接与用户约100ms的原生推理相减。

|配置|测量次数|平均 ms|P95 ms|数值判断|
|---|---:|---:|---:|---|
|普通 PyTorch，确定性，一次投影|80|205.37|213.60|基准|
|完整 CUDA Graph，确定性，一次投影|80|64.01|64.65|通过|
|拆分前后向 Graph，确定性，一次投影|80|64.22|64.86|通过|
|拆分前后向 Graph，确定性，四次投影|80|185.67|187.74|通过|
|局部 RMS/RoPE compile + Graph，一次投影|80|56.69|57.27|未通过，不采用|

拆分图的平均前向 23.60ms、单 VJP 40.40ms。四次反传合计 161.73ms。捕获含预热平均单投影 1.10s、四投影 2.59s；这是每个新 shape/执行配置的准备成本，表中是热态。当前实现逐请求释放图，生产服务需按 shape 预热并采用有界缓存；不能把冷捕获塞进实时请求。

## 为什么图优化有效

一次带 profiler 的前后向共 7145 个 GPU kernel，累积 kernel 时间约 53.49ms，矩阵乘约占自 CUDA 时间59%，attention backward约12%。普通实现包含大量 norm、RoPE、cast、切片反传、逐元素与小归约。完整 Graph 录制这些操作后一次发射，跳过逐算子的 Python/C++/驱动启动开销，未减少反传数量。profiler 会扰动墙钟，采用独立热测做速度结论；不把 profiler 的长墙钟当作正式延迟。

最初非确定性试探为普通191.72ms/Graph53.19ms，但重复 eager 自身梯度波动也超过既定容差。启用 deterministic algorithms 与 CUBLAS_WORKSPACE_CONFIG=:4096:8 后，普通与 Graph 的32项检查 raw 和梯度最大误差均为0，选层相同；拆分一/四投影另32项也全部为0，包括更换并恢复噪声。与上一轮八个 BF16 请求的一次投影选层也全部相同。53ms 分支保留作探索值，推荐引用64ms分支。

## 算子融合与反传 batching

仅局部编译 RMS/RoPE：首次调用约13.4秒，热态约56.7ms，比64ms再快约11%。但全部 raw 最大偏差 0.058594，门控梯度最大相对误差 10.40%，8请求的16项检查里选层改变 4 项；首五步平移误差最大 11.189mm。没有放宽容差来采用它。Inductor 融合低精度操作可能省略 eager 中间截断；专门复测保留截断选项后，raw 最大差 0.035156、梯度相对误差最大 18.35%、16项检查中选层改变 6 项，严格检查仍未通过。

四个反传 seed 放到同一批：约 162.67ms，比串行四次更快；但 attention backward、gelu、silu 等仍有 vmap fallback，梯度最大相对误差 2.65%，16项检查中选层改变 2 项，严格检查未通过。这轮采用标准不变，数值候选不冒充等价加速。未做完整模型长编译或手写 Triton backward。

## 流水线的收益与代价

固定一个请求的独立前后向图，在当前前向结束后，测“该请求反传+下一次无梯度前向”，20组交替串行/并发；下一次前向单独约 23.22ms。

|方式|反传完成 ms|下一前向完成 ms|两者都完成 ms|
|---|---:|---:|---:|
|串行|40.77|64.21|64.22|
|同卡双 stream，前向高优先级|54.80|26.91|54.80|

成对完成时间减少约 14.7%，但前向自身受资源争用而变慢，反传也延长。不能假设双 stream 可以将40ms反传完全隐藏。此为固定输入同卡争用微基准，不是闭环异步评测。

更适合的时序是先发当前动作，再利用机器人执行动作期间的 GPU 空档计算梯度，用于下一次重规划。它使用上一观测的选层信息，需要单独检查时效性和闭环效果；不能反过来给已经完成的当前前向选层。原生 Triton 无梯度前向不能自动供 PyTorch VJP 使用：如果保持原生服务另做一条影子梯度路径，新增计算仍是完整64ms；只有真正共用可微前向/激活，才可把新增成本记作约40ms反传。

## 当前建议

优先保留数值通过的 CUDA Graph 原型；一次投影已约64ms，四次投影也在当前小批热态内低于200ms。更低的在线预算宜采用动作执行空档、周期更新或观测变化触发；周期更新/复用属于算法时序改变，不能仅凭这轮速度给成功率结论。若每次选层成本 C、之后每次跳层节省 Δ，每 N 次更新一次的摊销约 C/N；应由实际 Δ 决定 N，而不是只看低于200ms。若要求每请求都额外只花10–20ms，当前严格通过的版本尚未达到。

本轮没有重跑已完成的闭环实验，也没有证明新时序闭环成功率。进一步原生前向接入和专用 VJP 需开发 backward 并保存所需激活，不能通过切换一个 graph 开关完成。
