# 混合Attention/FFN：4090硬件成本加权对照

用户于2026-11-01授权执行混合Attention/FFN选择，要求在RTX4090实测模块耗时，并比较成本加权与不加权。本轮独立于已经完成的FFN-only冻结矩阵，旧代码、manifest与有效结果保留。

## 研究问题与固定条件

低动作影响的Attention可能只省很少时间；影响稍大的FFN可能有更高省时收益。检验显式使用风险/可省毫秒能否改善混合选择。在同一成本窗口下，不加权方案本身已经具有成本约束；额外除以成本属于需要验证的启发式，不预设它更优。

- 原π0 checkpoint、BF16原生Triton，完整18层Action Expert，H50/R5。
- 周期Full-D10→Fast-D2×4；只在Full求一次正权VJP，门控34个，前5步×前7个raw维度，时间权重[1,2,4,8,16]/31。
- 正式比较固定为误差评分E和A/F各自残差外推。前两次Full用本结构原评分暖启动；第三次Full在step50从两次旧Full历史估计预测误差，先读历史后写当前，首个E-mask Fast在step55。
- Fast真正绕过所选A/F算子。Attention skip仍计算当前K/V；A补偿位于FFN前，F补偿位于FFN后。第18层保持原有KV路径。
- L1–L17每层四状态keep/A/F/AF；任意被跳模块的支持层互不相邻，同层AF允许。
- 沿用上轮同40个探索case：四suite×task1/3/5/7/9×init19/20，官方初态、env7、settling10、20Hz、控制器、步数上限、case/replan噪声及prompt保持。它们不是未见验证集。

## 原生硬件测量

从已固定的真实8输入库重放，不用随机张量冒充模型负载。单张当前空闲RTX4090独占运行有界探测，记录UUID、实际shape、checkpoint、协议、源码及输入hash。

分开测完整Attention（含QKV/RoPE、Attention及O）、保留KV-only成本、FFN、补偿读写以及A/F/AF三种实际跳过净收益。每层比较keep、A0/A+、F0/F+、AF0/AF+七路线；每路线1次预热、4次热测，顺序正反平衡。另有每输入20次公共预热、3次真实残差采集和4次profile/真残差注回核验。默认预计4976次原生D2请求，上限5000；全部预热和失败尝试计账。冷启动、profile开销与正式热测分列。

CUDA events只在阶段边界记录，编码结束后解析，逐请求真实wall另记。核验当前真实残差注回A/F/AF能恢复完整路径raw/actions与18层KV；raw/action既定atol=rtol=1e-5，失败保留，不调大容差。

冻结各层A/F/AF净省时中位数和MAD。正式成本使用带补偿的净省时；只接受可信的正收益，噪声和被禁状态如实记录。AF组合使用独立测得的c_AF，不假定等于c_A+c_F。

B4/B6沿用此前同卡原生实测整层skip4/6省时锚点（约4.26755/6.36979ms，准确值及源hash进入新manifest）；总成本窗口tau=0.5ms，不能逐模块累计放宽。新layer成本来自本次复测。

## 加权/不加权的公平对照

令s_A,s_F为同一次E-VJP得到的绝对分数，c_A,c_F为单独跳该模块、含补偿的可省毫秒。两个方案共享同一组满足真实float64成本窗口和间隔规则的候选：

|方案|最小化目标|
|---|---|
|U：不显式加权|Σ所跳模块s_m|
|W：硬件成本加权|Σ所跳模块s_m/c_m|

AF的目标为A与F目标相加，成本约束使用c_AF。单独模块非正成本的状态不允许成为加权分母；所有禁用状态在U/W共同候选集中一致处理。用精确合法序列枚举（17层共2,117,473种合法四状态序列）并按未量化的实测成本过滤，不做贪心近似，不离散化或放宽预算。候选保存为有hash的紧凑NPZ，Full选择CPU耗时单独计入。

正式4条件：B4_M-E-U+、B4_M-E-W+、B6_M-E-U+、B6_M-E-W+；各40例，共160条新闭环。不给R另扩闭环矩阵。旧F-E+/B-E+只在身份兼容时作历史质量背景，须重算其mask在新成本表中的成本，不冒充同服务时延对照。
