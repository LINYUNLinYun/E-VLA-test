# idea1 v3.4 E3：真实被拒draft的信息、修复与剩余动作初始化

40条strict父系统闭环完成，父系统成功37/40。共有1429个请求，其中1029个实际验证请求、208个零接受；固定规则抽取207个shadow请求，其中127个原零接受。选择每episode最早4个零接受、最早2个非零接受，不根据动作误差挑样。这批结果回答动作空间和修复机制问题，修复动作未执行，不能报告修复策略闭环成功率。

在原零接受样本上，draft平移与Full的跨样本Pearson为0.9360，保留了相关信息，但平移代理误差仍有9.401mm。同一V14条件增加到D10后为8.901mm；换为当前Full条件、仍用D2则为3.386mm。步数和条件不能混为一个问题，本批条件干预的差异更明显。

当前Full条件下，拒绝draft重加噪q0.3修复两步为7.348mm，上一轮剩余动作初始化为7.505mm；它们的AE成本约14.28/14.16ms，而直接fresh Full-D2为14.20ms。三者都需要当前Full条件。在主设置ε1修复→ε0参考的比较中，warm-start的平移代理误差更大，但该比较还含噪声身份差异，补充控制见下文。单凭“复用了信息”不能推出节省了完整fallback成本。

上述主比较的fresh Full-D2与参考共享生成噪声ε0，修复使用独立ε1，因此还包含噪声身份差异。补充试验固定全部207个样本，保持实际draft/剩余动作、当前Full条件与两步日程，只切换重加噪的ε0/ε1，并使用两个Full-D10参考；未根据结果增删样本。

## 成本解释

E3_requests.csv保存候选AE成本，E3_costs.csv保存当前Full条件构建、Full-D10 AE与整个shadow成本，原shadow JSON保存已付draft/verify和其他Full路由时间。使用当前Full KV的修复必须重新支付当前vision/VLM成本；不能免费借用参考Full，不能把两步AE快解释成完整fallback同样快。V14条件修复可复用同请求已构建的V14 KV，但仍新增AE；这些是分项测量，不声称已部署的端到端加速。E3父系统原策略wall与shadow额外wall分别记录，shadow不污染执行动作或模型内的Full缓存。

首若干拒绝请求是固定但有选择性的诊断样本，不代表所有拒绝的无偏分布；每个episode内请求相关。离线改进需要另行命名并冻结修复策略闭环实验才能判断任务质量，本轮不拼接父系统成绩。E2原文为空，因此未编造E2实验。
