# V12十条件：200条扩样与静态补偿周期化

mask=[2,3,5,14,16,17]，原π0 BF16 Triton，H50/R5；周期为Full-D10→两次V12-D2。四suite各10task、每task init19–23。补偿参数及rank8完全冻结。

加周期确实改善三种静态方法各自的成绩：channel从67提高到134/200，Hadamard从38提高到126/200，linear从9提高到75/200。但周期无补偿本身已达134/200；因此本轮没有证据表明这三种静态补偿在现有Full刷新之上提供额外正向收益。channel总分持平，Hadamard点估计低4个百分点且区间跨零，linear低29.5个百分点且探索区间完全为负。

历史方法的正向信号在扩样后更清楚：复用154/200（77.0%），相对周期无补偿提高10个百分点，探索95%区间[+1,+19]；外推169/200（84.5%），提高17.5个百分点，区间[+7,+27.5]。仅看新增160条，复用和外推分别提高10和18.125个百分点，区间仍高于零；结果不是只由原40条驱动。以上未校正多重比较，属于本次固定条件下的探索证据。

历史补偿的改善主要出现在Long：周期对照15/50，复用34/50，外推35/50；外推在Goal也从32提高到42/50。它们仍会破坏部分原本成功的case：复用恢复43例、增加23例失败，外推恢复48例、增加13例失败，不能将总成功率改善理解为逐case普遍改善。

同GPU模型服务串行B1，两个独立环境客户端按task分组交叠运行；四suite交错/独立数值门禁通过才启用双客户端，否则使用单客户端。新条件在Full轮不提取静态方法不需要的残差。历史缓存始终来自该候选自身路径。

组件摊销延迟复用前轮2160次独占模型测量，新静态周期按(Full+2×静态draft)/3估计，不声称新跑端到端微基准。实际策略wall/动作、RPC含队列、回合墙钟、动作/s见summary.csv；新增160的运行基础设施一致，原40包含历史单环境结果，分析运行成本优先使用new160。

固定组件估计中，周期无补偿、复用、外推都约66.9ms/请求，细小差异不足以认定谁更快。但真实新增160闭环中的策略ms/动作分别为14.30、15.88、15.33，复用/外推相对对照增加约11.0%/7.2%。各条件自由运行后的轨迹、请求组成及评测负载不同；组件近似等成本不能代替实际系统成本。这轮证明的是质量收益，尚未直接测量Spec验证器接受率。
