# E4：V14历史残差补偿闭环与部署成本

四suite各10 task、官方init19，40条/条件、共200条新闭环。原BF16 Triton π0，V14跳[3,4,9,11]，H50/R5；周期日程Full-D10→两次draft-D2。复用/外推缓存只来自各自路径已发生的Full，包含提取、补偿及刷新成本。无验证器或夹爪保护。

这轮尚未证明残差补偿进一步改善周期V14的整体收益。复用成功率不变，恢复2例、增加2例失败；外推净增加1例（+2.5个百分点），探索95%区间[-7.5,+12.5]跨零。外推的描述性改善集中在Long（6/10→8/10），Spatial从10/10降至9/10，不能据此事后选择suite策略。

补偿本身确实便宜：独占热态同输入测量中，两个补偿条件和周期V14均约69ms/请求，相对Full-D10约1.59×；没有额外加速证据，不能按小于0.5%的逐卡点估计差排序。实际自由闭环的策略ms/动作反而比周期V14高约4.1%/4.8%，回合吞吐也未提高；自由闭环轨迹与结束步数不同，这个差异不是纯补偿kernel的因果开销。相对纯V14的成功率提升，大部分已由周期Full刷新取得。
