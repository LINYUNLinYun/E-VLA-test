本轮包含原文的 E1–E4，不把前三项的完成替代整轮完成。E1 为 batch 吞吐探索，E2 为采样迭代内残差复用，E3 为命令外推方法替换，E4 为纯 FLASH draft 跨环境评测。

- E1：最多 60 分钟；E2、E3：各最多 90 分钟。记录准备、编译、计时、评测和等待 GPU 的实际耗时，不以修改起点掩盖超时。明确到达预算仍不可行的配置，不无限修复或扩容。
- 代码按用户此前要求由 GPT-6.1-sol medium 实现；主代理核对设计、原始结果和交付。代码置于 `preparations/idea1_v3_2/`，结果置于 `results/idea1_v3_2/`；不覆盖历史代码、checkpoint、原始数据。
- 只使用空闲 GPU。初次检查只有物理 GPU3 空闲，先给高优先级 E1；E3 直接 CPU 并行。仅当有实验等卡时检查空闲状态，间隔至少 30 秒；不终止其他人的进程。
- E1 未找到提升也是有效探索结论；E2/E3 同理。实验失败、技术无效与有效任务失败分开。
- 时间预算内优先跑通真实 checkpoint 和小规模验证，不重做每套件 10×50 的全量测试。

## 2. E1：真正的 batch，而非多个 worker 排队

以 π0 Full 原生 JAX、D10、H50、R5 为首个验证对象。先测 B1/B2/B4，B8 仅剩余时间和显存允许时测试。真实观测来自 v3.1 固定四套件 100 点 bank；每个样本有自己的状态、指令和显式随机噪声。模型、层数、采样次数、输入相机不改变。

1. 分别记录加载、首次编译、预热和完成输出的稳定态耗时；检查 B1 对原生路径，batch 对同输入同噪声逐样本 B1 的 raw/decoded 数值差。数值偏移不隐去；不把小数值相似直接当成闭环等价。
2. 同卡比较请求／秒、摊销单样本耗时、batch 完成延迟、显存和队列等待；每轮在取回结果后计时停止。batch 增大可能提升吞吐同时恶化单条延迟，分别报告。
3. 只有真实 microbenchmark 表明有收益且数值门禁可接受时，使用并发环境请求聚合的实际 batch 服务，进行固定 8 场景（四套件 task0、init0/1）的短闭环对照。沿用 lean I/O、环境复用；保持每环境动作队列和随机种子独立。
4. 对照也使用优化过的串行模型服务、同一数量环境 worker；不能把更多 worker 或少写数据的收益记作 batch 收益。记录 batch 实际占用分布、尾批填充、实际完成 episode、成功率和总墙钟。必要时追加 B1 回测控制漂移。

8 场景只用于工程可行性，不声称四套件标准成功率。bank 加速与实际评测加速必须分表。

## 3. E2：十次 Euler 更新，仅 0/3 做完整 AE Transformer

首测 π0 Full，沿用 D10 均匀 `t:1→0`，更新编号为 **0-based**。每次请求的 VLM prefix 重新计算，残差只在本次采样的十次更新内复用，不复用上一帧视觉 KV。

完整更新时记录 AE Transformer 叠层的 pre-final-norm 输出减去对应当前输入的 residual；近似更新时仍重新生成动作／状态／时间条件的 suffix embedding，再加缓存 residual，执行当前 final norm、动作输出头和 Euler 更新。不能把整次 velocity 缓存冒称为 Transformer residual 复用。精确的 dtype、norm/adaRMS 边界和实现公式写入结果 protocol。

门禁顺序：CPU 缓存重置及更新索引检查 → 每步刷新版本与原生 D10 的同真实输入／噪声 raw/decoded 对照 → 0/3 配置 AE 独占耗时与完整请求耗时 → 预算内的小规模闭环。首次编译不计稳定延迟，但计入总预算。

至少比较原生 D10 与 0/3；D2 作为不同算法的成本参照，不能将其质量和 0/3 混合。若近似输出出现非有限值或严重失真，保存证据并停止该配置。若闭环时间不足，报告明确的实际样本数，不以离线动作误差代替任务成功率。

输出包括四套件分母、有效成功率、实际末端 XYZ 和可选代表视频、启发式失败阶段；阶段只作行为进度描述，不直接归因为夹爪或接触错误。历史结果仅在 checkpoint、输入协议、种子和场景键匹配时作为配对参考。

## 4. E3：替代 Kalman 的因果外推

复用 v2.1 已完成的 Full 真实轨迹和同观测 V14 输出，**不重新跑 GPU**。历史方法的状态为平移控制命令及其变化量，不是位置＋姿态。主比较保持相同目标，不能把位置拟合结果和命令拟合混成同一误差表。

- calibration：四套件 task0、init0–4，共 20 episode／634 重规划点。
- evaluation：task1–9、init0–4，共 180 episode／6345 点。
- 预测时只可读取当前请求之前已执行动作；每条轨迹独立重置。未来 Full 动作仅作评分标签。
- 方法：加权局部多项式（不同阶数／窗口）、恒转向外推、短阶局部 VAR；对照 HoldLast、旧 Kalman、v2.1 冻结 Kalman 和同观测 V14。
- 参数仅用 calibration 选择；尽量按 init 分组交叉验证，固定候选数与 tail guard，禁止在 evaluation 反复选优。
- 主指标为前 1–5 步平移命令 L2；同时逐 offset 1–50、1–5／6–12／13–50 段统计；补充沿轨／横轨、时间对齐诊断及分阶段／suite 结果。沿轨方向无效或近零运动时标未知，不杜撰方向。
- `command×50 mm` 是原控制器目标增量差的代理，不是实际末端位置差。时间对齐若用未来标签寻优，仅为 oracle 诊断，不是可部署预测器。
- 保存校准网格、冻结赢家、完整测试结果、配对区间、图和数据身份；没有部署执行的外推不能声称提高任务成功率。

## 5. E4：跨环境比较的资格门禁

05:00 UTC更新：新的CPU指令预检已通过，后续按[零样本执行口径](idea1_v3_2_e4_zero_shot_protocol.md)填补适配并继续原请求内的实验，不更换或训练权重。先前询问是口径偏好、非新增权限要求；主代理采用显式冻结映射和Full对照，不声称收到用户回复。以下原先“等待确认”的分支由该细化协议替代，科学解释限制不变。

先核查已有 CALVIN、SimplerEnv、PushT 环境和权重。本地 FLASH draft 是四个 LIBERO suite 各自训练的 head；当前 V14 也源自 `pi0_libero`。跨数据集同时有 camera、状态、动作坐标／尺度、夹爪含义和控制频率变化。不能预设 V14 在其他环境必然可用，也不能为实现预期结论而任意更换权重。

三类环境分别记录：机器人／控制器、观测和动作规格、实际可用权重／归一化、映射方案、成功判定、是否具有 Full 正对照。PushT 原生为二维像素绝对目标，不可直接截取七维 LIBERO 动作前两维冒称合法迁移。

如有经过确认的映射且用户接受零样本迁移边界，先在一个兼容性较强的环境小规模比较 **Full、V14、纯 draft**，共用初始状态和指令，保留真实位置和视频；draft 不得偷偷调用 Full／AE。Full 也全失败时仅能结论为该跨域部署无效，不能证明 draft 的相对泛化劣势。

如缺目标环境匹配权重／经过确认的部署定义，记录具体缺口并征询，不用训练新 draft 或自行采购资源扩张本轮。E4 不可因 E1 截止而静默漏掉，也不可把环境 smoke test 写成策略评测。
