## 1. 已确认的研究意图与边界

1. E1：将 FLASH 的验证方法迁移到 π0 的 V14 draft。分别评估 **V14-D10＋verify** 和 **V14-D2＋verify**；Full fallback 固定 Full18-D10。每轮最多执行 5 个动作。
2. 验证的“单步”指在每个选定噪声时间点各做一次速度预测与端点重建；两个时间点并行，不是两次串行积分。
3. verifier 使用最近一次 **Full 路径**生成的 KV。V14 每轮读取最新观测，不能把 V14 KV 覆盖进 Full verifier cache。
4. E2：探索 π0.5 的 VLM 跳层能力；不预设一定比 π0 更耐剪。
5. E3：将上一轮实际执行动作作为约束，研究是否改善旧 Full KV 下的验证。承诺动作在本实验同步执行设定中按实际执行记录处理；不能使用尚未执行的未来信息。
6. E4：测原 FLASH **纯 learned draft model** 独立闭环，不含 AE 验证、周期 Full 或失败后的 Full 接管。它不同于论文中的 Flash-path only。
7. 已有 π0 Full-D10、Full-D2、V14-D10、V14-D2 成功率与延迟优先复用，**不得为凑齐新对照而重跑**。暂找不到 V14 对照，就先与已有 Full 比较并注明可比性，不阻塞新增实验。
8. 优化前先做有界 profiling，测实际整轮实验成本；只采用输出、状态隔离和吞吐验证通过的优化。
9. 本轮不训练模型，不新增 Kalman、action-expert 层裁剪、跨轮异步 VLM 更新；后者归 v3.1。不擅自延长执行窗口到 12。

本文包含首版工程选择，尤其 E3 的状态锚点，属于可实现的实验定义，不冒充已经被实验证明的模型机制。

## 3. P0：优化前 profiling 和加速选型

### 3.1 目标、对象与时间预算

目标是缩短完成固定评测清单的墙钟时间，兼顾单请求服务延迟；GPU utilization 只作解释信号。

先用既有、可运行的 π0/V14 路径测评测管线；E1 可用后，在其默认条件 `V14-D2 / tau0.15 / P2 / Rmax5` 上确认结果。不能把纯模型路径的最优配置未经确认直接用于带缓存、验证和 fallback 的系统。E2／E4 只做所选优化的短适配检查，不复制整个搜索。

**P0 测量预算：首次有可运行版本后累计不超过 60 分钟墙钟；不含等待 GPU 和首次模型下载。** 实现工作单独记录，不能用“优化还没完成”无限延期科学实验。最多评估 4 个执行配置（含原始配置），先依据瓶颈选择，禁止 compile×graph×并发数全组合搜索。到预算时采用已有正确、可用配置；候选无法公平比较就保留原配置，不宣布最快。

### 3.2 两层测量

**A. 固定真实输入的推理测试**

- 从已保存真实观测中冻结 20 个点，覆盖四 suite 和接近、接触／抓取、搬运、对齐等阶段；不是随机图片或随机状态。阶段不足时如实记录，不生成伪样本。
- 若缓存输入无法直接复用，从后述短闭环采样；不为收集输入另跑大批 Full 对照。
- 每配置最多 10 次预热，必要时上限 30；记录首次加载、编译和所有预热耗时。20 点×5 次=100 个测量请求，按相同输入序列及种子执行。
- 有状态 verifier 测试使用固定的 `obs/state/draft/Full KV/cache age/history` 案例，或者重放相同的请求序列；每次重放重置状态。不能在计时循环里无意不断增加 cache age。
- 独立记录 draft、verify、Full 路径；合成路由序列只能报告微基准，不冒充闭环平均速度。

**B. 短闭环吞吐测试**

- 固定四 suite 各 task0/init0，共 4 个 episode；所有候选使用相同模型、mask、D、节点、R、阈值、路由和最大环境步数。
- 原配置与最有希望候选做 A/B；时间允许才反向 B/A 复查。记录配置顺序、共享 CPU/I/O 负载，候选上限 4 个。
- 正常跑到 success／原生 timeout，不缩短 horizon 以提高表面吞吐。预算到达停止新 episode，在途正常排空；因此 60 分钟不是强杀 deadline。
- 若预算内未完成全部 episode，报告共同完整任务集和剩余进度；不能把不同难度任务的 episode/hour 直接比较。
- P0 是工程诊断，不混入科学成功率主表；其原始结果保留，不能静默删除失败。

### 3.3 必须计时的边界

使用单调墙钟计主线程区段；GPU 分项使用 CUDA events。详细 profiler 只对约 10 次请求开启，其余轻量记录。不得为了每个小区段计时而反复 `cuda.synchronize()`；只在正确读取 event／微基准边界同步。记录 profiler 开销，正式闭环关闭重型 tracing。

| 区段 | 应记录的内容 |
| --- | --- |
| 启动 | 权重加载、环境创建、编译次数、编译耗时、预热、图捕获 |
| 调度 | 队列等待、任务领取、锁等待及持锁时间；进度查询耗时 |
| 环境 | reset、物理 step、渲染、观测提取、遥测；能分开则分开 |
| RPC | 序列化／传输／服务排队／往返；若嵌套计时，注明包含关系 |
| 模型 | 图像编码、VLM、draft AE、verify AE、Full fallback AE、后处理 |
| 同步与复制 | CPU↔GPU 数据移动、等待 GPU、日志用 tensor 转 CPU |
| 保存 | enqueue、压缩、文件写入、fsync、NFS 同步、视频编码 |
| 校验与结束 | 结构检查、哈希、视频检查、最终提交、后台队列 drain |

嵌套区段不能相加两次；异步写入用独立时间线表示，不能把 writer 的总工时当主线程等待。给出 episode 墙钟的可解释分解和未归属残差，不强行凑出 100%。

输出：`profile_raw.jsonl`、`profile_summary.csv`、`profile_timeline.png`、`optimization_selection.md`。摘要至少有 mean/p50/p95、完整 episode 用时、环境 steps/s、重规划 requests/s、排队长度、CPU／GPU 活动与磁盘等待信号。成功和 timeout 分开列，防止“更早失败”被当成加速。

### 3.4 候选优化的优先级

| 优先级 | 候选 | 实施／采用边界 |
| --- | --- | --- |
| 1 | worker 预分片、独立结果日志 | 大文件校验移出全局锁；每个唯一任务只能有一个 owner |
| 1 | 合并 episode 数据、局部缓存、后台写入 | 优先本地高速盘（实际存在才用）；有限队列，空间不足停止派发；NFS 同步确认后才能记持久化完成 |
| 1 | 模型常驻，复用已编译路径 | 不按 episode 重载权重；固定科学参数，减少无意义形状变化 |
| 2 | 四卡独立服务／分片 | 首选每卡一个环境；显式绑定推理与 EGL 渲染设备，不能只绑定 server |
| 2 | 同卡两个环境覆盖仿真与推理等待 | 在锁／I/O 不再明显阻塞后试；不是天然 batching，不保证收益 |
| 3 | 真正的小 batch，B=2 | 仅瓶颈支持时作为候选；每环境 KV、history、RNG 和路由独立，不为凑 batch 无限等请求 |
| 按证据 | torch.compile、CUDA Graph 或现成 Triton | 先检查已有后端；只优化固定计算路径，不重新手写算子，不把 Python 路由／写盘一起强行捕图 |

compile 与 CUDA Graph 可能已组合存在，不能把它们当独立必加项。重点查看 kernel 启动空隙、graph breaks 和重复编译；不能仅凭 GPU 利用率低决定开图。参考 [PyTorch profiling 文档](https://docs.pytorch.org/docs/stable/torch.compiler_profiling_torch_compile)。

模型输入所需相机渲染必须保留；只减少额外展示帧、编码和重复读取。首次 capture／warmup 不计入热态请求延迟，但计入实验启动成本。

### 3.5 正确性、选型和退出条件

对固定真实输入做有限输出比较，并覆盖 Full→V14→verify→Full、episode reset、不同 prompt 长度、两个环境交错等状态切换。只改调度／I/O 时预期输出保持一致；改变数学后端时记录最大绝对／相对差、接受长度与夹爪分支差。容差依据 dtype 和已有数值基线预先规定，不能看到不一致后不断放宽。

执行选择依据：

`预计总耗时 = 启动/编译/预热 + 固定工作量的实测执行时间 + 最终保存/同步排空时间`。

- 优先选择上述总成本最低且数值、状态隔离通过的配置。不同 GPU 数量同时列墙钟和 GPU-hours。
- 改善不到约 10% 或波动遮盖差异时，选择更简单、稳定的配置；不宣称已证明提速。
- 新配置出现输出污染、重编译风暴、无持续收益或 writer 堆积，停止新派发，在 episode 边界恢复原配置。
- 保存选型依据及实际版本；不把吞吐优化收益归于研究方法。正式测速若多环境吞吐配置不可比，另用同后端单请求测量。

### 3.6 执行顺序：先定位，再改一个瓶颈

本节是执行者的操作协议，不承诺所有计时器已经存在。缺失的分项标 `not_measured`；RPC包含模型时延时，只列包含关系，不能把两者相加。不得为补齐漂亮的分解图无限增加插桩。

1. **冻结原配置A。** 记录代码revision／补丁、checkpoint、dtype、已有compile／graph配置、GPU型号与UUID、EGL绑定、CPU线程数、writer设置、负载和样本清单。确认现有代码是否已经使用编译或图重放，不能把“重复打开开关”当优化。
2. **先跑A，不修改实现。** 保存启动到首个可用请求的时间、短闭环各episode总耗时及轻量分项。从真实请求中冻结微基准输入；仅对约10次请求开详细trace，其余关闭。先回答GPU在算、等输入，还是CPU在仿真／写盘。
3. **用墙钟占比排瓶颈。** 优先处理主线程实际等待占比最高的项。即使GPU推理加速很大，若其仅占总墙钟的一小部分，整体收益也有限。不能把GPU utilization的低值直接等同“缺少并发”。
4. **一次只试一个改动。** 候选B先做固定输入正确性和reset／缓存隔离检查，再做微基准；明显无收益或不一致立即淘汰，不进入闭环。最多3个候选，不构建全组合矩阵。
5. **最有希望的B才做短闭环A/B。** 对比共同完成的四个episode；若控制流已分叉，补列实际动作数、重规划数、成功／timeout与路线变化。不同工作量的总用时不能简单相除称工程加速比。相同输入的微基准用于隔离计算收益，闭环用于确认整个管线没有退化。
6. **冻结所选配置并交接。** 记录采用／拒绝理由、失败项和未测项。正式科学运行不热切换数学后端；必要调整在episode边界创建明确的执行revision，保留此前有效结果。

| 观察到的主要现象 | 优先尝试 | 不应先做 |
| --- | --- | --- |
| 模型服务空等，环境reset／render／step占主导 | 查EGL实际绑定、环境与服务串行边界；有余量才试同卡双环境 | 直接叠加compile与CUDA Graph并宣称解决 |
| 保存／锁等待明显，GPU间歇空闲 | worker独立日志、episode级合并、有限后台队列 | 无界缓存、取消必要遥测或把未落盘当完成 |
| 输入预处理／RPC占主导 | 缓存不变文本／配置、减少重复转换与小包，保持每轮新观测 | 跨不同闭环复用视觉KV，改变科学协议换速度 |
| GPU持续计算且有大量短kernel／启动空隙 | 只测试固定形状路径的现有compile／graph机制 | 捕获动态路由、跨episode共享可变缓存 |
| 多环境加入后排队、p95或总耗时恶化 | 比较单环境与双环境，排空后回退 | 因“利用率更高”继续堆环境 |

### 3.7 三张表与采用判据

P0最少交付下列三张表；数字必须来自实际日志，缺测项留空并说明，不能用理论FLOPs推算代替实测。

- **启动／微基准表：** 每个配置的加载、编译／capture、预热、测量请求数、mean／p50／p95、是否发生测量期重编译、输出最大差、路由／接受长度一致性。冷请求与热请求分开；若测量期仍有首次形状编译，同时列混合分布，不把100次统称纯热态。
- **闭环成本表：** 相同key的success、环境步、请求数、总墙钟、RPC／环境／保存／等待分项与残差、writer排空、GPU-hours。原始完整episode和共同工作集都保留，不只展示提速案例。
- **选型表：** A/B改动、真实覆盖、正确性是否通过、推理收益、闭环收益、启动额外成本、采用／拒绝／证据不足、代码版本。若没有受控对比，不写“优化有效”。

对于固定工作量，可用 `N_break_even = 额外启动成本 / 每请求节省时间` 粗估编译回本次数；仅当分母为正、输入／路由分布相当时有意义。动态路由优先直接估算固定清单总耗时，不能把只测verified路径的节省外推到全部请求。

优化采用门槛仍以3.5为准：数值与状态安全先通过，总成本有可辨别改善才采用。小样本支持工程选择，不足以宣称稳定的论文级加速；不为得到显著数字扩大测速规模。

## 4. 通用评测协议与预算

### 4.1 样本、版本和去重

四套件为 `libero_spatial/object/goal/10`，每 suite 10 个任务。正式扩展默认每任务 init6–10（0-based），每条件 **200 episode**，不做 10×50。

- E1 超参试跑：每 suite task0、5，init0，共 8 条／候选。校准结果与后续 init6–10 分开汇总；任务仍有重合，不叫跨任务独立盲测。
- E1/E3/E4 首批：各条件先全部 40 个任务的 init6，得到均衡 40 条初表，再扩到 200。
- E2 第一批同为 40 条，用于选候选；新增 init7–10 作为未用于该次选型的结果单列。
- key 至少包括 experiment、完整科学配置 hash、checkpoint、suite/task/init、种子规则。编译 revision 另记，不改变科学 key；不同处理不能错误去重。
- 已成功和已失败的有效 episode 都保留。技术 invalid 单列；修复后只重试该唯一 key，保存旧尝试，最多一次自动的已诊断重试，再失败则只暂停对应配置。
- 不同候选可以各自闭环；只有真实 obs/state 完全相同的离线比较才允许共享 VLM 特征。不能跨已经分叉的轨迹复用观测或 Full 动作。

### 4.2 固定与匹配项

π0 沿用既有 checkpoint、预处理、动作解码、控制频率 20 Hz、H50；R 为 `min(接受长度,5)`，Full／纯 draft 每轮最多 5，成功或终止时截断。最大仿真步数沿用已有 suite 配置，不因弱模型失败多而延长／缩短。

同步 LIBERO 的物理时间按环境 step 推进，推理等待期间不额外推进物理世界。20 Hz 是仿真控制时间步，不等于测出的实际墙钟控制频率；本轮不能仅凭推理更快就宣称动态物体场景成功率提高。记录观测采集到动作输出的墙钟延迟，但不为模拟 staleness 人为插入 sleep 或额外环境步。

D2 固定均匀 `1→0.5→0`，D10 完整覆盖 `1→0`；不是截取原 D10 的前两步。本轮不继续搜索采样节点。

种子沿用现有任务／init／replan 规则；generation 和 verify 使用分开的确定性 RNG 域，避免 verifier 多一次调用改变后续 draft 的噪声。保存实际规则。优化 A/B 重放必须使用相同噪声；闭环路由分叉后不能声称每轮物理时刻仍配对。

## 5. E1：V14 draft＋单步重建验证

### 5.1 条件与搜索

VLM 为 V14_A03，1-based skip `[3,4,9,11]`，完整 AE，保留既有 KV shell 语义。draft D∈{2,10}；Full 路径一律 Full18-D10。

验证固定 K=2，代码的剩余噪声坐标 `t∈{0.10,0.05}`，两个分支共享同一份 verifier 噪声，批量并行：

```text
x_t = (1-t) * a_draft + t * epsilon
a_hat(t) = x_t - t * v_full_AE(x_t, t | latest_Full_KV, current_state)
```

每个未来动作先在模型归一化空间比较前六维：`dist = L2(a_hat-a_draft)/sqrt(6)`；两分支均满足阈值的最长连续前缀才接受。夹爪另处理，距离不是毫米或空间半径。

校准网格：`tau={0.10,0.15,0.25}`，`P={2,4}`，共 12 条件（含 D）。P 表示连续完成 P 次 draft 推理轮次后，下一轮强制 Full；不是 P 个环境步。校准不额外扩网格。

每个 D 保留参考 `tau=.15,P=2` 和一个校准选中配置；相同则去重。选择顺序：校准成功数优先，其次每实际执行动作的推理耗时，再优先较小阈值／较小 P。保存全部候选结果；选中不称统计最优。正式样本最高分仅作探索观察，不据其继续无限调参。

### 5.2 缓存与路由状态机

每个 episode 独立维护 `Full KV + 生成轮次/环境步/观测时间/版本`、当前 V14 临时 KV、实际执行历史、计数器、夹爪状态和 RNG。共享底层权重时，Full cache 必须拥有独立有效存储，防止 CUDA Graph/V14 前向覆盖缓冲区。

1. reset 清空所有跨轮状态。首次无 Full KV 时执行 Full-D10，保存 KV，执行最多5步。
2. 达到周期 Full 条件时直接执行 Full，刷新 KV 和计数器；不先无谓计算 draft。
3. 其余轮次获取最新 obs/state，计算 V14 draft；verifier 使用旧 Full KV 和**最新 state**。
4. 沿用 FLASH 的夹爪检查定义、阈值0和 Full window=1；明确记录 verify-gripper 与 post-verify 截断，不能只保存一个“失败”标签。检查窗口限拟执行的未来最多5步。
5. 接受前缀 L>0 时执行原 draft 的前 `min(L,5)` 步，不执行重建平均值或未经验证尾部。夹爪规则要求接管时遵守其 Full 调度规则。
6. L=0 时不推进环境，立刻走 Full-D10 并刷新缓存；同一物理状态只执行最终选中的动作。验证与被拒 draft 的时间仍计入本次总耗时。客户端即使通过下一次 RPC 完成 fallback，也不能在中间执行未接受动作。
7. 保存实际执行步数与新 state；下一轮重新取观测，周期 Full 或拒绝回退后计数归零。

不要只设置 `full_fallback=False` 或改 CLI 就认定实现符合本方案；需读实际 server/client 控制流。重建输出只是检验依据，不自动替代 draft。

### 5.3 指标和结论边界

- 质量：总体／suite／task 成功率；有同 key 历史对照才给恢复成功、新增失败和配对差。
- 路由：Full 总调用率；启动／周期／零接受／夹爪原因；每轮和每执行动作两种分母；接受前缀长度分布；KV 年龄（轮次、环境步与墙钟）。
- 成本：draft、verify、Full、被拒绝的额外开销；混合路由的总推理时间／实际动作数；请求 p50/p95；与历史基线匹配程度。
- 误差：保存候选与重建在未来1–5步的每轴有符号差、平移／旋转分组和夹爪方向；不是与“真值动作”的差。
- 相比纯 V14 的提升归于整套 verify＋周期／夹爪回退系统；不证明 verify 单独贡献，不证明 Full 消除了已有累计误差。
- “通过验证”是旧条件下局部一致性的弱信号；不能证明视觉新鲜或任务正确。τ 接近宽松上限带来的高接受率不能独立当收益。

成本按整个 episode 的实际调用累加：`T_policy = Σ(draft + verify + Full + 实际模型输入输出处理)`，不重叠计时；再除实际执行动作数给出每动作成本。一次验证失败后接 Full 必须包含两者，接受短前缀导致重规划增加也必须体现；只报“成功接受那次请求多快”会高估收益。

## 6. E2：π0.5 的 VLM 跳层可操作性

中优先级，与 E1 无科学依赖。有空闲卡和已就绪模型即可并行，不能阻塞 E1/E4。

### 6.1 模型与首批候选

先定位真实可用的 LIBERO π0.5 checkpoint，记录其官方／本地来源、配置、归一化、H 和 action expert 参数。模型与环境放 `policies/<项目>/`、`.venv`，新环境 prompt 与项目名一致。已有环境优先复用，不为本轮训练或重新微调。

不能只看到代码中的 `pi05=True` 就认定已持有可用权重。当前本地 π0.5 LIBERO 配置有 H10 的例子，应以实际 checkpoint 配置为准，**不强行改成 H50**；Rmax 仍为5。所有 mask 使用同一 checkpoint 的完整 action expert、原生采样日程和 D，以隔离 VLM 跳层影响。

首批 Full＋4个既有 mask，不做新的离线筛选：按历史配置定位 V16_A02、V15_A08、V14_A03、V13_Custom 的原始1-based列表，先冻结实际层号，禁止仅凭名字猜测。若前两者无法及时定位，可用明确后备 `[3,9]`、`[3,9,11]`，但命名为新 transfer mask，不能冒称历史 V16/V15。

V14 为 `[3,4,9,11]`；用户 V13_Custom 保留 `[1,2,5,6,8,9,10,11,13,14,16,17,18]`，在18层架构上对应 skip `[3,4,7,12,15]`。实际模型若非18层，不做未经解释的编号映射；该分支先记录兼容性问题。

### 6.2 评测与扩展

先各40条（四suite×10任务×init6）。选择两个跳层候选扩到 init6–10：一个首批成功率最高者，一个在成功率距最高者不超过10个百分点内跳层最多者；重合则只保留一个。规则只决定实验资源分配，不宣称最优。Full 同步扩展以形成匹配参照；已有完全匹配的 π0.5 Full 则复用，不新跑。

新 π0.5 Full 是该模型自身必要参考，不是重测被禁止的已有 π0 Full。如果没有可用 checkpoint，仅 E2 标待资源，其他实验继续。

报告成功率与相对自身 Full 的下降、VLM／AE／总延迟、suite 差异和层数。不能拿不同 checkpoint 的绝对成功率直接宣称 π0.5 更耐剪；本轮也不由多个 mask 的表现定位单层因果作用。

## 7. E3：已执行动作前缀约束 verifier

### 7.1 假设与依赖

依赖 E1 的正确实现和一个已冻结的 V14-D2 父配置，优先使用 E1-D2 校准选中配置，其他参数不变。E1 成功率一般也可继续检验，不把80%之类阈值当运行门槛。

假设：已执行动作提供运动历史约束，可能改善旧 Full KV 下的下一段动作重建。不是因为旧 KV 会自动把当前预测编号从1–5改成6–10；KV 没有这样的动作时间指针。

### 7.2 首版时间锚点和输入定义

设 n 为重规划轮次、k 为当前累计环境步；上一轮起点为 k−r，实际执行 r∈[1,5] 个动作。Full KV 可能来自更早轮次，始终复用最近一次 Full 的同一份 cache。

本方案首版采用**上一轮起点为锚点的前缀约束**，这是工程选择：

| 项目 | 定义 |
| --- | --- |
| 当前 draft | 最新 obs/state 下的 V14-D2 预测，H50 |
| verifier state | 上一轮执行前真实保存的 state，时间 k−r |
| verifier 动作前缀 | 实际执行的历史 r 步，位置1–r |
| verifier 未来部分 | 当前 draft 的前50−r步，位置r+1–50 |
| 验证与执行窗口 | 只比较位置r+1–r+5与当前 draft 前5步；按实际可用长度截断 |
| 历史约束 | 前缀不加噪声、重建后保持固定，不计入接受距离，不再执行 |

保持 H50，不把输入临时缩成10步；默认 r=5 时才是“历史1–5＋当前未来6–10”。若相对最初 Full 时刻编号，可能已经是更后位置，不能混用两种锚点。

历史动作须与实际发送控制器的命令对应，保留模型空间、解码命令、clip／gripper 后处理记录。当前 draft 与历史前缀必须转换到**同一锚点、坐标系及归一化**；若 decoder 使用相对 state 的 absolute/delta 转换，先明确可逆映射和重锚规则，不能直接拼接不同参考系张量。无法正确实现时只暂停 E3，不延迟其他实验。

在 t=.10/.05 的两个分支中，未来部分按 E1 加噪与重建，历史部分按用户设想保持干净。原 AE 通常使用 chunk 级时间条件，没有训练好的逐 token“历史干净／未来带噪”协议。因此首版**不新增未训练的 history token、独立时间 embedding 或 attention mask**，保留原 chunk 级 t，明确这是分布变化的启发式输入。实现需保证历史 prefix 对未来位置可见。

无上一轮历史时走 E1 规则；不补造五个动作。历史来自实际上一次执行（Full 或 draft），拒绝而未执行的动作不入历史；零接受 fallback 不推进历史时间。

### 7.3 对照与解释

父条件直接复用 E1 的当前 state、无前缀结果，不重复跑。首版只增加这一个 E3 条件，先40条再200条。

比较成功率、接受长度、Full比例、未来1–5误差、夹爪、KV age 和时延。历史前缀被固定成零误差，不能把它算进平均值制造“误差降低”。分别列 r=1–4与r=5、Full后首轮和连续draft轮次。

该处理同时引入历史前缀、时间重锚与较旧 state，因此收益只归于**完整前缀约束方案**，不能单独归因历史信息；失败也可能源于混合噪声输入或状态锚点变化。若有明确收益，再把相同锚点的去历史消融、当前状态显式历史输入等放下一轮，本轮不展开。

## 8. E4：原 FLASH learned draft 独立闭环

高优先级，与 E1 无依赖；checkpoint 就绪可立即并行。

- 使用原 FLASH 的 suite 对应已训练 draft checkpoint 和它依赖的图像编码、语言／state／history 输入、action head 及解码。不把 V14 称为这个 draft。
- 每轮读取最新观测，draft 直接生成动作，执行前5步。**不调用 AE verifier，不做首次 Full bootstrap，不做周期或夹爪 Full 接管。** 视觉编码器仍需要计算。
- 沿用 draft 原生 H（预期50，以权重及代码核实），历史状态按其训练／服务实现初始化与更新，禁止用 Full 结果填充历史提高成绩。
- 四suite需要正确的对应权重，缺某suite则单列缺口；不能拿 Goal 权重冒充所有suite模型，也不为补齐而训练。
- 先每suite全部10任务的init6，共40条；再补init7–10，总200条。与已有 Full 对比，历史口径不一致明确标注。
- 保存成功率、真实XYZ、失败阶段和 image encoder／draft head／总时延；同时检查路由日志中 AE验证=0、Full调用=0，防止测成 Flash-path only。

论文已报告 Flash-path only，不等于已报告这里的纯 draft-only。参考 [FLASH 论文](https://arxiv.org/html/2605.13778) 和 [本地项目说明](../../../policies/realtime-vla-flash/README.md)。纯draft低成功率也是有效结论，不触发重试或修改执行窗口。

## 9. 数据、可视化与轻量质量检查

### 9.1 全量轻量记录

每 episode 保存：唯一key、配置与版本、来源／种子、success/timeout/invalid、真实EEF xyz、姿态、夹爪、物体／接触／抓取遥测及可用性、实际执行动作、每次重规划当前状态和时间、阶段标签及unknown。

结构检查覆盖所有episode：长度／维度、有限值、动作与实际执行对应、唯一key、路由一致性、必要字段、保存完成状态。正常任务失败是有效数据。校验不需要重复读取全部旧checkpoint、raw或重新完整解码全部视频。

### 9.2 视频和真实XYZ

- 每条件、每suite固定 task0/init6 与 task5/init6 保存完整视频，最多8条／条件；这些key在看结果前固定。其余默认保存XYZ和轻量遥测，不宣称所有episode均有视频。
- 视频正确性先用小样本检查codec、色彩、方向、fps、帧数、完整解码。正式入选视频各做一次解码检查，不叠加第二轮全量媒体任务。
- baseline蓝色半透明点线，variant橙色半透明虚线，标起止点和时间方向；提供XYZ三维视图、XY/XZ/YZ投影与共同时间距离。灰色阶段边界标明属于哪个策略。
- 轨迹来自仿真真实EEF；动作空间误差不能换个单位冒充末端误差。同时间差混合路线差与快慢差；共同长度截断后不能补零。
- 优先选择固定视频key中可配对的成功／新增失败案例，缺对应类别就明确缺失，不额外重跑只为挑图。全部XYZ可按事后明确规则选图，注明选择方式。
- Markdown 图片和索引采用相对路径；MPE查看视频提供HTML链接与明确文件路径，不能把截图当轨迹图。

### 9.3 成功率与失败分析

结果表同时列分子／分母、suite/task和实际覆盖；历史对照匹配时才给配对 bootstrap（按suite分层、task聚类，1000次足够本轮）。小样本和选型偏差如实标注，不为统计显著性追加全量实验。

分阶段保留接近、接触／抓取、搬运、对齐／释放、unknown。分别统计失败最远阶段、首次显著偏离、夹爪切换／抓取丢失候选事件；不能把最远阶段直接称致败阶段。E1/E3额外统计每阶段的拒绝率、误差和Full使用率，给观测数和episode数，避免长轨迹压倒短轨迹。

## 10. 四卡调度、运行恢复和完成口径

### 10.1 调度

- 首先可用GPU完成P0的单卡基准；其他卡可以做模型／数据准备。工程配置选定后，E1优先两卡分片，E4优先一卡，已就绪E2占其余卡；这是队列优先级，不绑定固定物理卡。
- E3就绪后接入空闲卡。某模型资源缺失不占卡等，不阻塞其他项目。所有卡可用就充分利用；少卡也立即推进。
- 仅任务等待且无可用卡时每30秒扫描一次；本方占用全部可用卡时依靠任务完成事件调度，不频繁扫描本方进程。
- 真正验证物理GPU UUID、推理服务、仿真EGL设备绑定和owner；不能把设备节点FD等同活跃渲染归属，不停止他人进程。
- 正式科学条件在episode开始前固定。调度优化可以改变任务执行顺序，但不能泄露其他环境缓存或改变每key的种子。
- 单请求延迟测试占一张卡、只测代表性已选条件，每条件约100次测量；其他卡继续闭环，注明共享CPU/存储负载。最多测8个新增代表条件，不把全部校准候选都再大批测速。
