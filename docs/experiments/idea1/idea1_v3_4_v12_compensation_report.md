# 指定V12与五种补偿：闭环及部署成本

四suite各10 task、官方init19，40条/条件、共280条新闭环。原BF16 Triton π0，V12跳[2,3,5,14,16,17]，H50/R5；纯V12及三种静态补偿全程D2；后三个周期条件为Full-D10→两次draft-D2。复用/外推缓存只来自各自路径已发生的Full，包含提取、补偿及刷新成本。无验证器或夹爪保护。

本轮三种静态补偿均未改善成功数：纯V12为14/40，channel/Hadamard/linear为11/8/2。周期Full刷新本身把成功数提高至25/40；复用和外推再提高至29/40、31/40。外推的点估计最高，但相对周期对照的成功率差探索95%区间为[-5.0,+32.5]个百分点；复用为[-10.0,+30.0]，两者均跨零，不能确认总体稳定提升。

历史方法存在明显的成功/失败交换：复用相对周期对照恢复10例、增加6例失败；外推恢复11例、增加5例失败。不能将它们相对纯V12的全部37.5/42.5个百分点改善归给补偿，周期Full刷新已经贡献27.5个百分点的点估计改善。

补偿计算本身较轻：channel/linear相对纯V12的固定输入额外耗时约0.10/0.14ms；当前Hadamard张量实现约3.73ms。计入刷新后，三个周期条件均约66.9ms/请求，相对同输入Full-D10约1.62×。逐卡小于0.5%的周期路径差异只作点估计，不能据此排序谁更快；相比纯V12约46.1ms，周期策略付出了约45%的请求耗时增长。

以下是初态一致性修复后的最终结果。最终核验发现4个case的复用环境首观测不一致；这些case全部七条件使用独立环境、构建前seed7重做，原28条记录保存在initialization_revision/original，不与新记录混合。修复后的40个case均逐一核对七条件首请求观测一致。修复重跑含服务准备约286秒，模型、参数、case、noise及日程均未更改；[技术修复方案](idea1_v3_4_v12_initialization_revision.md)和原始记录均保留。
