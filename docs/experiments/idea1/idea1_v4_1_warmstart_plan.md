# v4.1：Kalman 草稿的流匹配起点调参

用户授权继续验证更合适的流匹配起点。保留 v4.0 的 Kalman xyz 预测（姿态和夹爪保持）、坐标转换、V12/skip6、四方向选择器、周期3、Full残差刷新、外推、验证和环境协议；不叠加动态预算或外推误差评分。encoder、AE、验证均不上图，选择器图保留。

开始GPU运行前核对部署实现时发现：既有自定义D1/D2时间编码采用`arange(0,1024,2)/1024`，即i/512；官方JAX/PyTorch及D10导出使用`linspace(0,1,512)`，即i/511。t=1时，CPU时间嵌入的相对L2差约0.563，不能称为舍入误差；动作影响尚待测量。新候选及新Gaussian D2均统一使用正确频率，Full-D10导出权重保持不变。为隔离修正效果，Gaussian D2对照新增完整40例；旧40例D2只作历史参照。原计划/manifest与诊断保存在`attempts/pre_gpu_time_embedding_review`，此时无本轮GPU结果。

初值采用 `x_tau=(1-tau)*KF_raw + rho*tau*epsilon`，从 `tau` 积分到0，D1步长为 `-tau`，D2为两个 `-tau/2`。epsilon复用每请求原生seed，后25维的KF分量为零；加噪覆盖全部32维。tau取0.05/0.10/0.20/0.35/0.50/0.75，rho取0/0.5/1，D取1/2，共36组。rho=1对应按原训练线性路径加噪，rho<1是单独标记的探索条件；均不保证与真实训练边缘分布一致。

1. 在上一轮Gaussian D2控制轨迹的四套件task0/2、init19中，每例取最多6个已有输入的Fast请求。复用该轨迹实际选层和实际Full历史，Kalman只吸收当前时刻之前已执行的动作。同观测、mask、prefix和显式epsilon比较36组，补新旧Gaussian D1/D2、旧接法KF@t1和未修正KF。参考为同观测Full-D10；报告前5步动作误差、夹爪符号、验证接受率和AE耗时。离线误差不等同于闭环质量。
2. 按平均前5步七维解码命令MSE选每种D最好的2组；四候选与新Gaussian D2对照分别跑上述8例闭环，同case轮换顺序。每种D按成功数优先、热态均摊策略耗时其次确定1名；不因有效失败重跑。
3. 冻结D1/D2两名候选，在其余32例跑确认，并同时补齐修正Gaussian D2的其余32例。分别报告8例调参结果、32例确认结果和40例探索总数；旧40例Full只在协议兼容时复用，旧D2不充当修正后的主对照。旧数据此前已观察，32例是本次参数选择留出，不宣称完全未见基准。

新增闭环上限136回合（8×5+32×3）。若无空卡每30秒检查，不终止其他用户进程；空卡获得独占租约后启动持久服务，最多4卡。计时统一沿用v4.0去除前三请求及显式选择器捕获后的策略ms/实际动作，包含Kalman预测/编码/混合、ack和末次选择器排空。另列准备、AE和闭环墙钟。

只做新增机制所需检查：旧时间编码下tau=1,rho=1还原旧Gaussian D1/D2；修正编码下同一epsilon得到一致的Gaussian入口；时间频率端点、短区间节点与dt一致；有限输出、实际NFE及因果Kalman计数。结束后写结果并释放本次租约。
