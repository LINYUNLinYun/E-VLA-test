# idea1 v3.1：执行方案与边界

日期：2026-10-20设计、10-21开始执行。依据用户更新后的 `idea1.md`「v3.1 新增主线」。本轮与 idea2 分开管理；idea2已完整完成并审计后才启动本轮。当前真实进度见[执行状态](idea1_v3_1_execution_status.md)。

## 1. 三项要求与先后顺序

1. E2 评测吞吐优化（高优先级）：小批量 profiling，选择确实更快的运行配置。
2. E3 vision encoder 跳层（高优先级）：完整27层 baseline；保留24/21/18/15层，各5种 mask。
3. E1 XR0／CogACT VLM 跳层（中优先级）：探索最大可跳层数，成功率至少保留完整 baseline 的70%。

阈值是相对保留率，例如 baseline 90% 时门槛为63%，不是一律要求70%成功率。原始成功数、分母、四套件表现与相对比值一起报告，不将单个套件满分替代总体结果。

## 2. E2：快验证优先的评测系统优化

先对真实观测做少量 warmup + 同卡配对测速，再对固定小批 episode 测吞吐。区分模型请求延迟与 episode/小时；共享卡结果不能作为独占延迟证据。

候选逐项验证，不一开始叠加：

- 关闭非必要的视频编码、每步截图与大数组持久化，仅保留验证所需日志；策略输入相机仍必须渲染。视觉模型不允许以「不录像」为由关闭输入图像。
- 同 task 复用环境对象，严格每 episode reset RNG 与官方初始状态，核对 paired init hash。
- 正式v2默认不复用质量评测环境；只有同模型E2八场景的结果／输入／显式噪声／动作配对通过且测得吞吐收益，才可显式开启。不能因为代码支持就默认采用未验证优化。
- 同卡最多2个 rollout worker；与单 worker 在相同任务预算下比较 aggregate episode 吞吐。GPU利用率不是唯一验收指标。
- 既有 eager／compile／CUDA Graph 路径分别 warmup；小批量检查相同输入与噪声输出一致，再测试是否回本。动态任务或形状导致重新编译时单独记录。
- 多卡采用任务级独立分片，各进程模型与环境隔离；不把不同卡的延迟混合成模型加速比。

每项先4–8个配对 episode + 20 warmup/100 requests。只有测量确认收益且成功判定、输入和输出保持一致才上线。推理前后同步边界明确；不用 enqueue 时间冒充 GPU完成时间。记录退化结果，不追求一定达到10–50%收益。

10-21补充验证登记（原32条profiling完成后、采用优化前）：原生Full跨进程有同输入／噪声数值变化，故增加**同一持续模型服务**下的四种原profile配置，各用相同8场景，另存目录，不覆盖原数据。统一一次parity＋20warmup；每个配置前后固定5真实观测控制，decoded动作仍用1e-5，raw若原RPC不提供则记不可用、不由decoded推造。每配置的首8场景输入额外等量保存，用于比对原始图像与数值state；这是各组共同的小额观察I/O，计入arm墙钟并披露。两worker仍共享串行RPC模型，不是batch。

采用判断分开：固定输入的预测数值必须一致，官方初态／初始数值状态／成功结果须配对；自由闭环中只对相同input/noise的请求直接比动作，不把观测不同后的累计差异误称为调度数值错误。若仍出现未解释的初态、图像或结果变化，不直接上线环境复用。新证据不自动绕过旧的采用检查，须在报告中明确做出采用／不采用决定。该次π0.5补充限定32条，不无界重复测试。

10-21 00:42采用记录：π0.5同服务32条独立审计通过，四组各8/8成功；各优化组254/254请求的输入／噪声／decoded动作与基线逐项一致，初始图像与数值状态一致，40次固定控制动作最大差0。双worker墙钟113.87→55.45秒，吞吐2.053×，因此仅对π0.5显式采用环境复用＋2worker。原跨进程四组数据和失败采用观察均保留，不以新数据覆盖。质量数据另存同服务验证根目录，通过索引与其他模型的数据组合，不重复计算已有科学样本。

其他模型不能由π0.5外推。为缩短仍在执行的大矩阵，追加一次有界的同协议外部有效性检查：π0、XR0、CogACT各四组×8场景＝32条，共96条；每模型使用自己的原生Full、同一持续服务、相同固定输入前后控制和独立审计，不改D/H/R或NN源码。只在空闲卡、已运行条件自然结束后执行；采用必须逐模型通过原冻结reuse gate及配对／数值／结果／吞吐检查。若不通过，保留原单worker队列，不反复调参至通过。质量队列切换只能发生在完整condition结束后，已有效完成的任务键跳过，不能为采用优化重跑已有结果。该补充属于E2运行配置验证，不新增跳层搜索预算。

### 2.1 可选的中间相机渲染优化：有界验证登记（10-21 04:08，尚未实测）

## 3. E3：27层 vision encoder 的跳层实验

π0 与 π0.5 分开，以各自原 checkpoint、原 action horizon、D10、R5为主矩阵；不同时改 VLM或AE层。两者的结果不能合并分母。

每模型21条件：Full27 + Keep24/21/18/15，每档5个独立 mask。仅跳完整 vision transformer residual block；保留 patch embedding、位置编码、最终 norm、projector与256个空间token，保持原始层编号。记录跳过／保留的完整列表。

五类预先固定的布局：均匀分散、前中段、后中段、相邻短段、固定seed随机（先按整数规则生成唯一列表并封存，遇重复顺延，不根据成功率暗改）。允许相邻跳层；不同裁剪强度不能机械套用同一 mask。若分析指标可用，仅作为布局参考，不设离线精筛淘汰闭环候选。

首轮每条件4套件×10task×1init=40episodes；每档取总体最高的候选补到5init（200episodes），Full同样补到5init。若某档结果已近零，仍保留首轮结果，但不为无明显价值的候选补量；说明缺少精确估计，不宣称全空间不可能。候选选拔与最终数据共享时明确属于探索性数据，非独立确认集。

测速同卡、同真实观测、同噪声，20warmup/100measure；单列所有相机合计vision latency、模型请求总延迟与各自speedup。至少每档1个代表mask测量，避免只有成功率没有性能。代表视频和XYZ按预定少量场景保存，其余不录像；XYZ不能用相机截图代替。

### 3.1 正式vision筛选前的门槛澄清（10-21，尚无mask质量数据）

首次跨进程native Full／all27 selected-scan比较出现0.0024–0.0030最大动作差，原failed receipt和两份benchmark保留，不覆盖。但E2中完全不修改的π0.5 native Full换进程也有同量级变化：8个场景首请求的input/noise hash全部一致，动作最大差0.00098–0.00265。因此不能把跨进程差异直接归因于vision wrapper。

已完成的π0同模型同进程诊断中，native独立重trace、exact v2 selected-scan和无gather辅助对照，在3相机×27层×4节点、encoded/projected输出及完整D10 raw动作上均逐位相同。此证据不支持改写生产NN或放宽容差。

正式E0改用**同一已加载模型内**的native／native重trace／exact selected-scan比较，π0与π0.5分别做：固定原benchmark前两条，再补其余未覆盖suite的首条（通常5条真实输入）；保持同预处理、显式噪声、完整原D10和输出转换，逐层、raw及decoded仍用原 `atol=rtol=1e-5`。两个模型各有独立gate artifact，未通过不启动vision mask评测。跨进程benchmark仍用于真实延迟测量，其动作变化另作重现性观察，不能冒充该门槛通过或失败的唯一原因。

使用新增同进程验收／审计模块，v2生产vision、模型、采样源文件与manifest保持不变。新版审计只有在两个同进程gate的原始肯定证据完整且hash一致时，才替换旧的跨进程等值要求；原failed检查和观测继续呈现，其他缺失／错误、E2采用门槛及前沿扩展要求不变。这是比较方法修正，不是调大数值容差。

### 3.2 变体测速前登记：新的同卡计时批次与负载漂移检查

首批Full微基准与最后变体测速可能相隔数小时，且共享主机的其他评测负载会变化。因此每模型的正式性能表使用一个新的、只读NN路径的计时批次：同一物理GPU上依次运行原生Full-before、π系的all27 selected-scan Full参考、预先选定的代表变体、原生Full-after。每项仍20次预热＋100个唯一真实bank输入；全部保持该模型的原D/H/R、精度、相机与模型源码。新增的是短请求重放，不重跑Full任务成功率或已有质量episode。

代表选择不变：vision每个预算至少一个完整首筛中的最高成功数布局，平分按condition ID排序；低成功率预算仍测一个代表，但不能称等质量加速。E1主要测已完成确认、达到相对70%门槛的最高跳层候选；无合格候选时只能报告探索性失败点的延迟，不宣传为可用加速方案。选择与测速用不同指标，不能按速度反过来改写质量排名。

主加速比以本批Full-before的P50为分母，另列matched Full比率。Full-after用于漂移检查：完整RPC与vision两项P50分别计算相对before的变化，任一主报告项变化超过10%即标记该批不稳定（分项标记同时保留），不自动挑更有利的分母，也不无限重测到得到正收益。不能因vision仅占完整请求一小部分，就以RPC稳定掩盖vision本身的漂移。保留所有原值与P95/P99；报告单独的vision完成时间与完整RPC完成时间，不将两者相减或简单相加作为额外模块耗时。

每项调用原冻结controller／benchmark并另留独立目录，原始benchmark中pre-parity health字段不改写；其同PID的真实loaded-protocol肯定状态及parity凭据独立保存，不能再因后续质量评测覆盖而丢失。新的cohort审计核对bank、100个input／noise／seed、H/R/D、同物理卡身份及完成输出。不同变体动作不要求与Full相同（其差异正是消融效果），只核对各自原生适配repeatability及已通过的结构门槛。

原先Full／matched benchmark与旧跨进程差异文件必须保留，旧vision gate仍引用原路径／哈希。若为覆盖审计登记变体benchmark副本，只允许填入尚不存在的文件并附真实cohort来源；不覆盖旧Full或matched文件，不把不同批次／不同卡的旧Full与新mask直接算成主加速比。最终质量数据索引和新cohort性能来源分开交代。

## 4. E1：XR0／CogACT 最大跳层探索

- XR0：完整D2作为主要同采样基线，复用已选skip12作为参照；从跳12层向15/18/21/24层递增。每档先5个布局，跨均匀、短连续、相邻对及指标参考；高裁剪档若全崩溃，可向相邻档补5种布局，而不是认定不存在更好方案。
- CogACT：主要使用原生DDIM D10完整模型作同采样基线，先跳9/12/15/18层。CogACT不是flow matching，不套π的积分步长解释。已有skip9相邻对作参照，允许短连续布局。调过的D2日程若补测，另表报告，并与相同日程Full比较。
- 实际depth、跨模块KV依赖以已加载模型确认；保留原层索引的hidden-update bypass与既有协议一致，action expert不剪。
- 每候选先40episodes，直接闭环评测，不以低相关性的离线分数筛到只剩极少数。每档候选最高者若接近／超过相对70%门槛，则补到200episodes。
- 相对阈值使用同模型同采样同任务集合的新Full；旧数据只作参考，不混用分母。报告最大跳层的已测试可用候选，而不是全空间最优。
- 前沿扩展规则：不能因为预设预算到头就停止。若XR0跳24层、或CogACT跳18层的最佳候选在补量后仍达到相对70%门槛，则分别继续测试XR0跳27/30层、CogACT跳21/24层（逐档，每档5种预先固定布局）；若筛选值落在60–70%附近，先补量再决定。扩展以独立不可覆盖manifest登记，引用原baseline与原始manifest哈希，明确初始矩阵与条件触发扩展，不事后改写已有记录。若新前沿都明显低于门槛，停止继续增加裁剪数，并注明这不是全组合空间的不可行证明。
- 有界终止补充（初始高预算结果产生前登记）：若上述新增末档仍在200条中保留至少70%，继续到现有mask生成器允许的边界档：XR0跳32层、CogACT跳25层，各仍5个预先冻结布局、同样40→选中200规则。边界来自已冻结保护层及至少保留一个未保护block的限制，不是模型理论最少深度；触及边界后只能称「当前允许布局／预算范围内最高已测可用点」。若某档最佳已确认低于70%，停止向更高预算推进，不把这一停止当作未测组合必然失败的证明。没有触发就不运行这些扩展，不为凑范围增加无效评测。
