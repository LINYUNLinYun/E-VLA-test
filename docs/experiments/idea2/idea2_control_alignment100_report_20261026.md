# π0.5 动作延迟补偿：100 场景配对扩样

状态：200/200 条有效回合全部完成，统计通过，我方 GPU 服务已退出、租约已释放。

**异步未补偿为84/100，动作前缀补偿为96/100，提高12个百分点；配对救回15例、损失3例。40-task聚类95%区间为[+4.04,+20.22]个百分点，精确双侧McNemar p=0.00754。剔除最初小批后改善仍存在。** 这支持保留补偿方向，但不能称逐场景无损或与同步策略等价。

用户在八场景小批后要求扩大评测。固定四套件各25个初始场景，共100场景；每个场景分别运行原异步控制与动作前缀补偿。完整 π0.5、D10/H10/R5、VLM lead3、AE16/Prefix112 SM、下一帧 Encoder 重叠、两槽 KV、原种子规则均沿用小批实现。

**唯一主要比较是同一异步控制协议下的未补偿/补偿差异。** 补偿在 R5 交接时按已发生的控制步计算输入年龄 d，执行预测索引 d…d+4；不足 R5 时停止并记预测时域耗尽，计入失败，不补动作。它修正时间索引，不能让旧观测变新，也不是 RTC/inpainting。

## 固定样本与复用

- 四套件 Object、Spatial、Goal、Long；每个 task0–9 的 init0/1，加偶数 task 的 init2，各25场景。
- 两条件各100条，总计200条；小批的16条兼容记录只计一次，新增184条。
- 小批中两个未补偿失败保留。模型、控制客户端和服务端计算代码未改，只扩展评测矩阵与运行编排。
- 同步路线已有200场景/条件的有效记录；相同100场景的同步全新 KV 为96/100、同步SM16为97/100，单列为历史参考。它们不是与本轮同控制时序的主要统计对照。

## 预定统计

主要报告配对救回/损失数、成功率差、精确双侧 McNemar 和40个task聚类 bootstrap95%区间（10000次，seed20261026）。另报不含已观察小批的92对敏感性分析及各套件结果。不将统计不显著解释为无损，未设非劣界限。

记录输入年龄、跳过步数、残余索引错位、实际动作值、时域耗尽、稳态 RPC、整回合工作墙钟、GPU Event 窗口和重捕获。不同控制协议的时间不混合成 GPU 加速比，本轮不采 nsys。

## 运行与资源记录

原计划同一场景的两条件在同一GPU运行，按suite/task/init轮换顺序，GPU3先运行、GPU2空闲后加入。GPU2第一次启动在空闲检查通过后遇到未登记外部进程，占用21.73GiB导致模型加载OOM；该次尚无episode，保留技术记录。GPU3原分片继续完成，此后未再使用GPU2。按用户允许改用其他空卡的指示，后续使用GPU0与GPU3；最终99对同卡、1对因资源中断跨卡，详情与敏感性分析见下文。

有效任务失败不重试。遇到技术中断保留原目录，只补尚未运行的配对单元。

**观测没有变新，改变的是开始执行哪一步预测动作。** 补偿组3,057个非bootstrap消费块中，跳过2/3/4/5步分别为849/2,176/24/8次，随后仍执行R5（成功终止或原生任务步数上限可截短）。残余时间索引错位为0，不代表物理状态预测误差为0。

## 剩余四个失败

| 补偿失败场景 | 终止原因 | 未补偿结果 |
|---|---|---|
| Object/task2/init0 | 跑满280步 | 成功 |
| Object/task4/init2 | 预测时域不足，30步停止 | 成功 |
| Goal/task6/init0 | 跑满300步 | 成功 |
| Long/task8/init2 | 跑满520步 | 也失败 |

Object/task4/init2在实际控制步30交接时，候选观测来自步24，需跳过6步；H10只剩4步，无法满足R5。按预定规则停止并计入失败，未删掉这个回合，也未把它作为技术错误重试。另三例是普通任务失败，目前没有逐一证实的单一根因。

接下来值得单独测试的最小修正是：时域不足时在R5边界拒绝过期候选、等待较新结果，而非直接终止；同时报告这带来的控制停顿/SLO。还需要检查普通失败中的动作/夹爪时间对齐。**本轮没有把这些尚未验证的修正混入100例结果。**

## 资源中断、核验和可复现性

最初GPU2发生模型加载OOM，零episode；其余已有GPU3回合保留。用户随后允许使用其他空卡，调度改为核实空闲的GPU0+GPU3，见[资源修订](../../../results/idea2/control_alignment100_20261026/resource_gpu0_revision.json)。GPU0后来出现未登记外部进程，资源检查中止我方客户端和服务；保留已有效的7条，只在GPU3补完中断/未启动的9条。

因此Spatial/task9/init1的一对分别位于GPU0和GPU3（同型号RTX4090）。该例两条件都成功，bootstrap输入/seed与输出数值核验一致；上表另报排除此例的99对结果。其他99对同卡。所有资源调整只影响运行编排，模型、控制客户端、D/H/R、KV协议和固定案例网格保持一致。两次外部进程均未被我方停止；有效任务失败没有重试到成功。

200个有效回合共32,680次预测、37,505个实际动作。100组配对bootstrap的decoded/normalized动作MAE与max均为0，沿用MAE≤1e-6、max≤1e-5容差。每个有效回合的真实执行动作均核验为原预测数组的声明索引；两KV Slot、实际16/112 SM、噪声身份和回合reset协议检查通过。稳态Graph重捕获为0；bootstrap/捕获不计入稳态RPC。

所有采用数据对应的运行期源码检查通过；GPU0中断分片服务正常退出且源码未变，已完成回合有独立客户端退出/资源/动作核验记录。原模型和控制实现未改，只新增扩样编排、资源恢复与统计脚本。当前没有GPU队列，租约均已释放。
