# FLASH source normalization and target-noise audit (2026-11-04)

**Conclusion:** the inspected training/inference implementation uses the base checkpoint's normalization contract, with no per-suite normalization switch driven by the draft-source dataset. However, the four published draft checkpoints do not preserve enough training provenance to prove that their actual cache-generation runs used identical normalization files. This remains a bounded provenance uncertainty, not evidence of a known normalization mismatch.

No runtime, manifest, queue, experimental outcome, or selection was changed. No GPU work was launched. Large model weights were not rehashed. Published `.pt` metadata was read on CPU using `weights_only=True, mmap=True`; the extracted fields are in `released_head_metadata_20261104.json`.

## 4. Does this require a source-to-target coordinate conversion?

No source-specific norm map was found in the inspected code or released metadata, so there is no evidence-based correction to insert into the existing experiment. Under the documented/common code contract, changing only the source head while retaining the shared base transforms is the intended implementation.

If independent evidence later shows a head was trained with a different state/action normalization or extra-delta convention, its input must use that source state transform, its prediction must be decoded using the corresponding source output transform into LIBERO physical control space, and any target verifier must receive the re-encoded target action representation. Recomputing statistics from each suite, or simply choosing a target-suite normalizer, would not establish the correct source contract. Such a correction would require a new explicitly named experimental condition; no historical result should be silently changed.

Thus the current cross-suite results establish the behavior of released heads swapped under a fixed common Pi0 inference contract. They can support an operational source-head transfer limitation. Until the missing training provenance is available, they should not be described as fully isolating task-distribution generalization from every possible training-preprocessing mismatch. No actual mismatch has been demonstrated by this audit.

## 5. Zero-noise teacher training is not zero-noise online target inference

The published `teacher_zero_noise` metadata agrees with `enc_cache.py:258`: the teacher cache uses all-zero diffusion noise. This describes the **training target construction**.

Online serving has a different default:

- `spec_serve_policy.py:81` defaults `ablation_noise_seed=None`. Its `infer` entrypoint accepts optional noise; lines730–743 pass explicit noise if supplied, otherwise leave it absent unless the optional seeded-ablation path is enabled.
- The default fast input path in `triton_pi0_runtime.py:828` fills a float32 noise buffer with `.normal_()` and copies it to BF16. The slow path at line879 uses `torch.randn(..., dtype=float32)` and then converts to BF16. These are standard-normal draws, not zeros.
- The compiled/PyTorch paths agree: `spec_pi0_pytorch.py:817` calls `sample_noise` when noise is absent; `pi0_pytorch.py:211` defines mean0/std1 Gaussian sampling, and its ordinary `sample_actions` uses it at line418.
- The Triton draft head itself takes prefix/state and no diffusion-noise argument (`pi0_spec_infer.py:2084`). Online verification receives the sampled noise (`triton_pi0_runtime.py:1835–1840`); Full sampling also consumes it.

The frozen experiment wrapper explicitly generates `numpy.default_rng(case_seed).standard_normal((50,32)).astype(float32)` at `preparations/ease_insights_20261103/draft/server.py:126`, then passes it to native infer at line135. The seed is determined by suite/task/init/replan and excludes source/mode (`draft/common.py:28`). It is **paired Gaussian noise, not zero noise**. Pure draft records but does not consume it.

Therefore this experiment does not introduce a new zero-versus-random online contract relative to the inspected official/default server: both use standard-normal target noise. It does replace the default Torch/CUDA RNG stream with an explicit NumPy/CPU case-indexed stream, so exact noise realizations and RNG/data-transfer overhead differ. Cross-source pairing is by case/replan identity; observations and replan histories may diverge in closed loop. These facts limit exact numerical or timing equivalence to default unpaired serving, without implying any particular paper-level performance change.

The wrapper's recorded `policy_wall_ms` surrounds the native `original_infer` call; CPU seed generation/input hashing occur before that timer, while the client RPC includes wrapper overhead and response transport. Accordingly, native-policy cost and full client RPC must remain separately labeled. Neither may be called an exact reproduction of default-serving latency merely because the ideal noise distribution matches. No noise setting or executed condition was modified in this audit.
