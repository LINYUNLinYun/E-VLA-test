# 初始输入校验中断后的技术恢复

AE12/D4 的一个分片在 libero_goal/task03/init45 的首次输入配对门报错，发生在该案例的模型预测之前。失败时未保存原始观测，因此无法确定具体差异字段或原因。原错误和身份文件已按原字节归档；使用相同 GPU/EGL、seed、官方初态及十步 settling 的独立环境诊断，重新得到预期输入哈希和噪声 seed。诊断没有加载 VLA 或执行策略动作。

[恢复计划](resume_plan.json)固定了失败服务、诊断、原科学 manifest 和恢复前243条有效案例。通过独立资源请求0006续跑，模型、采样器、输入门和168个冻结源文件均未改变。恢复服务只生成此前未完成的18条案例，没有重跑已接受的案例；原失败案例这次通过同一个严格输入门。

[保留记录证明](accepted_preservation_snapshot.json)确认243条案例的原始科学文件均未改变。冻结的 `recover_case` 重建了其中22份管理收据，只改变 `worker_pid` 字段，并留下恢复账本；不能据此声称所有管理收据字节也未变化。

原选择器已规定成本只使用有完整 `result.json` 的服务。中断服务已有22条有效科学案例，却没有完整服务结果，因此其成本探针被排除，22条案例仍保留在完整质量分析中。原验收脚本没有处理这一额外的不完整服务；[独立验收修订](acceptance_amendment.json)另行固定新验收器，只允许这一处已记录的服务排除，仍要求320条新案例、160条原控制和8个完整成本服务。科学选择规则、阈值和独立统计决策函数保持不变。

六项临时记录测试覆盖：仅识别指定中断服务、拒绝已完成或被修改的服务、严格限制成本排除集合与完整服务数量、只允许管理收据作者变化、拒绝原始科学文件变化、拒绝诊断变化。全部通过。CPU自动验收程序等待全体案例和八个分片完成，再验收、独立重算并冻结候选；它不会启动 GPU 任务。
