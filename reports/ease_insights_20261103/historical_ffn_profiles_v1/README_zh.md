# 历史 FFN 敏感度：候选搜索，未获得稳定候选

按解码分数前冻结的协议，检查旧模块实验 B6_F-R+ 的40个初始Full记录：四个suite，各5个task、初态19/20。仅读取module_score_0.npy，未读取成功率文件、动作数组、后续帧或当前C7结果。每个案例17层分数归一化后，先在task内平均初态，再等权平均task。

枚举924个不相邻、固定跳过6个FFN的组合，保留150个总体代理分数接近最优的组合。按suite选择候选后，有一对在全数据上满足预定相反侧重门槛；但逐task留出、用其余task重新拟合路径时，预定双向稳定性条件未通过。因此结果为no_proxy_candidate，不基于这份代理分析启动新GPU分支。

[协议](protocol.json)、[完整分析](analysis.json)保留所有候选比较与留出诊断，独立逐项求和实现与矩阵实现选择一致。这些是D10 Jacobian对动作的敏感度，不是带残差补偿的FastD2损失，更不是闭环成功率证据。当前C7固定注意力／FFN比较不受本分析影响。
