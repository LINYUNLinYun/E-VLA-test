# VLM／AE模块路径的实现准备

此页保留较早CPU准备截面。现已通过两服务各488项GPU数值/执行门及四个已知Full案例的逐位动作桥接，并启动320条新模块路径发现集；当前状态与证据见[实验记录](../module_tradeoff_v1/README_zh.md)。下面“未通过GPU门”描述的是当时状态，不代表当前状态。

仅完成CPU准备，10项调度/清理检查和4项周期策略检查通过；没有构造模型、模拟器或CUDA上下文，没有选择路径组合、冻结科学清单或通过GPU数值门。正在运行的四条VLM几何路径及其源码均未修改。

当前D2实际走eager adapter的18层循环，不读取历史native decoder的层注册表。新准备代码在本进程内临时包装其实际`_decoder_layer`调用，保持原D10/D2采样函数、fused权重、时间日程、噪声、KV拷贝和解码不变，只对明确层号执行AE跳过；退出或异常后还原本进程函数绑定。FullD10强制保留AE18；真实调用顺序必须是每个NFE依次访问18个原层位，才能生成执行收据。不会把注册表配置当作实际剪层证据。

CPU检查覆盖：Full调用顺序和返回值、D2实际跳层、从1计层号、异常恢复、拒绝重入、未知函数绑定、错误顺序/NFE、原采样器只调用一次、Full不得剪层，以及不能报告未观测的NFE。另验证保留完整VLM时仍执行D10→D2→D2的AE路径，避免空VLM mask令旧策略始终Full回退；配置切换会清空自己的时间/残差历史。源码hash和CPU证据见[新版准备记录](CPU_preparation_v2.json)，原10项的记录保留。原采样函数内导入/18层循环的[源桥接核验](source_bridge_validation.json)通过，但这些检查不能替代GPU原始动作/解码数值等价验证，也不是成功率或加速证据。

若后续需要该分支，应先在原四suite有限bank验证无AE跳过时D10/D2对原采样器的raw/decoded等价、实际剪层记录、相同噪声与物理输入，以及Full刷新/路径历史的完整周期。随后按实际固定输入成本校准模块预算，再另立任务和独立复验设计；不把AE层数与VLM层数相等当作成本相等，不自动启动新的科学任务。
