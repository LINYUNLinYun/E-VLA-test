# Resident backend feasibility (source-only)

**Decision:** A single serialized Pi0/VLM backend can serve the fixed mask conditions at episode/condition boundaries without changing the VLM or AE algorithms. The backend already takes the VLM layer selection per call; the present within-suite server is what pins one condition to one process. This is a future, separately versioned engineering path, not a change to `vlm_within_suite_v1` and not evidence about condition quality.

The distinction is process/backend residency versus one immutable CUDA runtime object for every prompt. The current adapter retains one active prompt-length `Pi0Inference`; when prompt length changes it clears that runtime, calls `torch.cuda.empty_cache()`, and recreates its CUDA weights/buffers. A resident server therefore avoids condition-level server/model startup, but source alone does **not** guarantee identical model tensor allocations across all prompts. The new version should keep invariant checkpoint weights in shared live storage/context and change only shape-dependent scratch buffers; language embeddings remain prompt-length data and are updated per prompt. `Pi0Inference` already separates weight and buffer dictionaries, but `language_embeds` currently sits in the former, so the refactor must explicitly separate it before sharing the invariant weights. Validate that refactor before relying on it. Measure that lifecycle in the future gate; do not claim otherwise.

## Source findings

- The six whitelisted configurations are fixed: all use `H=50`, `R=5`, `refresh_D=10`; `full_d10` has no skip mask and always runs D10. Masked conditions use `period=2`, `D=2`, extrapolation, and these exact one-based masks: `jac_anchor=(2,3,5,14,16,17)`, `local_spatial=(2,3,5,13,16,17)`, `local_object=(2,3,5,14,15,17)`, `local_goal=(2,3,11,14,16,17)`, `local_long=(2,3,5,12,16,17)`. After each policy configure/reset, masked conditions route `Full-D10 → Fast-D2 → Fast-D2`, then refresh. Full route captures residuals for that condition's mask; fast routes use that mask and its own last two full-refresh residual maps. The full vision pass and full AE refresh are retained. (`vlm_within_suite_v1/common.py:19-47`; `vlm/policy.py:14-50`.)
- `vlm.Backend.prepare_residual` accepts per-call `skip` and `capture_layers` (layers 1–17), checks that current/older history keys exactly match the skip set, and forwards them into its eager encoder. `TritonBackend.prepare` similarly builds `vlm_layer_indices` from its `skip` argument. The lower `transformer_encoder` accepts/validates per-call layer indices. No fixed-mask cache or backend re-instantiation is required by these call paths. (`vlm/backend.py:8-85`; `idea1_v3/policy.py:56-93`; `pi0_infer.py:922-1006`.)
- The hard condition pin is in the current service protocol: startup takes one `--condition`, records it in protocol, and rejects a different configure request (`server.py:46-58,97-106,124-129`). The wrapper policy itself accepts any exact whitelist entry and calls `reset()`; that reset clears `pending`, `round`, `step`, `draft_rounds`, residual `history`, and `counts` (`within_suite_v1/policy.py:6-11`; `vlm/policy.py:14-24`). The server/worker identity checks also require a fixed `condition_id` (`worker.py:196-203`), and the current runner starts a server/worker per condition (`runner.py:97-110`). These versioned wrappers, rather than the backend mask API, prevent switching today.
- Mutable per-request model buffers include normalized images/state, VLM hidden/K/V and AE diffusion-noise buffers. Preparation overwrites the new observation and language embedding; sampling copies the context state/K/V and constructs `(50,32)` noise from the supplied seed. Keep the backend serialized: `prepare_residual` temporarily replaces module-global `pi0_infer.transformer_encoder` and restores it in `finally`. The existing one-stateful-worker RPC path is compatible; concurrent inference on this global hook is not evidenced safe. (`idea1_v3/policy.py:56-93,115-118`; `vlm/backend.py:68-78`; `pi0_adapter.py:95-106,135-174`.)
- The adapter's `scripts.experiment10.backend.Backend` owns the checkpoint/transform and keeps `runtime`, `length`, graph/schedule caches. It uses one active runtime length; a length change clears runtime/graphs/schedules, calls GC/cache release, and builds a new `Pi0Inference` (`backend.py:45-78`). This is a prompt-shape lifecycle caveat, independent of condition mask. The same adapter selects fresh prompt embeddings and updates observation inputs. Per-call AE schedules are keyed/cached by runtime and nodes; `sample` receives the requested D and records actual NFE in its local `nodes` audit (`pi0_adapter.py:108-174`).
- Existing episode flow already calls `configure(config)` before prediction for each case, pairs env seed 7, and derives a deterministic model seed from `(suite, task, init, prediction index)`; it then enforces `R=5` and acknowledged actions (`rollout.py:35-60,63-79`). Preserve those boundaries/seeds, and never carry a residual map across cases or conditions. Do not carry `pending` across a switch.

## Smallest future architecture

Create a separately named resident runtime package/manifest, leaving all pinned v1 source and outputs untouched. Start one server per explicitly assigned GPU UUID; construct one backend and one active policy; keep one stateful worker and serialize predict/ack/configure. Keep the real invariant checkpoint weights, reusable D10/D2 schedule tensors, and CUDA context allocated through condition boundaries and CPU-only analysis; configuration resets policy state only and must not call `empty_cache` or destroy model allocations. For prompt-length changes, share invariant weight storage, treat language embeddings as prompt data, and replace only shape-dependent scratch buffers rather than constructing a second full set of weights. The current adapter's schedule cache is keyed by runtime identity and flow nodes (`pi0_adapter.py:108-133`); a separately pinned adapter may key reusable schedule tensors by checkpoint and nodes. At an episode boundary, require the prior proposal acknowledged, call `configure` with that case's exact whitelisted config, and reset policy state. At a condition boundary, use the same operation with the next frozen config. Continue to save each episode under its own condition/case key and retain the prescribed case order, H/R/D, mask, full vision/AE paths, seeds, and prompt/input pairing.

Budget live model memory from a future measured peak plus modest headroom, not a dummy allocation: for example, a measured 8 GiB working need could justify a 10 GiB resource budget. That is an example only; the current operating observation supplied for this preparation is about 11.5 GiB for the EASE process, not a source guarantee or universal requirement. Measure the actual model/shape/cache peak and headroom before choosing a reservation. Keep the same process/context/real allocations across condition gaps so another allocator cannot take the freed space; do not treat a logical lease or the old ~64 MiB context holder as equivalent residency.

Give the resident process a stable `resident_session_id` plus server PID and GPU UUID. Give each episode/condition segment its own condition ID, config, manifest hash, run ID, and technical revision. Health responses and receipts must report the active condition and the same resident PID/session; do not reuse the current single-condition protocol identity. The new global resource and research manifests must hash/pin the resident wrapper and every reused backend source, with the new runtime revision name and explicit condition-switch protocol. Existing `runtime_revision()` names `vlm-within-suite-isolated-runtime-v1`, identifies the frozen wrappers/backend reuse, and says legacy sources are unchanged (`common.py:138-146`); that identity cannot represent the new server. Do not hotpatch these pinned sources or claim the old protocol stayed identical.

## Bounded future validation contract (GPU work only when separately scheduled)

1. On the existing finite gate, run the four old-bank observations through all six fixed masks on frozen and resident implementations, paired by input/seed. Preserve the existing gate comparator and QK check; do not relax tolerances. The gate explicitly covers only four old observations, not the 24 LIBERO90 tasks or all 20 task prompts (`server.py:18-25`).
2. Add deterministic replay on at most one already-saved real initial request per distinct LIBERO90 prompt (target coverage: all 20; report absent prompts). On one resident PID, run all six condition segments in a fixed recorded order, configuring between segments; in each segment replay five requests with canonical per-index seeds and acknowledge the same R5 prefix. This exercises Full/D2/D2/Full/D2 inside each masked condition, mask switching, residual-map identity/history reset, and condition alternation while holding the real observation fixed. Compare frozen and resident raw outputs, decoded actions, noise hashes, routes/history metadata, and requested versus **actual** NFE using the unchanged finite-gate comparator for numeric outputs. This is request/state parity only, not closed-loop or quality evidence.
3. Prove residency separately: one server PID/session and GPU UUID across condition switches and CPU analysis; stable invariant-weight allocation/context across all masks and prompt lengths; record prompt-embedding and scratch-runtime identity plus legitimate buffer replacements. Verify no condition/episode boundary calls `empty_cache`, no duplicate full-weight allocation, and model bytes plus profiled headroom remain live. Compare server/model initialization count and wall time. The current formal receipt explicitly says `actual_NFE_exported=False` even though backend sample auditing has an `actual_NFE` value (`worker.py:118-127`; `pi0_adapter.py:167-173`), so a future receipt must expose the observed count rather than infer it from requested D. Stop on output, input/seed, identity, or memory-contract mismatch. No quality/complementarity claim follows from this gate.

No model imports, GPU work, query execution, process signaling, current episode outcome inspection, implementation, or current-branch source edits were performed for this note.
